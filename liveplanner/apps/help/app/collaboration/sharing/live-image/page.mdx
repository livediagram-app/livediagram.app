A live image is a plain image URL for one tab of a project that **follows the project as it changes**: the server keeps an SVG snapshot that is redrawn on the first load after each save, so wherever you place the URL shows the current state of the plan. It is the companion to an [embed](/help/collaboration/sharing/embeds/): the embed is interactive (open cards, live updates), while a live image is a single static picture, which is exactly what you need somewhere an `<iframe>` is not allowed, like a **GitHub README** or a Markdown file.

## What the image shows

The image is a flat picture of the tab, drawn from what it holds:

- **A Board** is drawn as its columns with their cards.
- **A Sheet** is drawn as its cells, showing their worked-out values.
- **A Form** is drawn as respondents see it, on the form's own look.
- **A Dashboard** is drawn as its layout: each metric and chart appears as a labelled outline (such as **Metric** or the chart's kind) rather than the live figures. Use an [embed](/help/collaboration/sharing/embeds/) to show a Dashboard's charts.

A tab with nothing on it yet (one still on **Start Planning**) has no image.

## How it differs from an embed

Both come from a share link and both stay current, but they suit different homes:

- An **embed** is an interactive frame: readers can scroll the board, open cards, and watch it update in real time. Best for wikis, Notion, and your own pages.
- A **live image** is a static SVG served at a URL. Nothing in it can be clicked, but it drops into anywhere that accepts an image, including places that strip iframes. The server refreshes its snapshot after the project is saved, so the image catches up to your edits on the next load.

## Getting a live image

<Step n={1}>Open the **Share** dialog and create or pick a pass for the project.</Step>
<Step n={2}>Open the pass's **Live image** menu, beside **Embed**, and choose the format you need: **Copy image URL** for the bare link, **Copy Markdown** for a `![liveplanner tab](…)` snippet, or **Copy HTML** for an `<img>` tag.</Step>
<Step n={3}>Paste it where you want the tab to appear. A README takes the Markdown; a web page takes the HTML or the raw URL.</Step>

The image serves a cached snapshot that is redrawn on the first load after the project is saved, so editing the project updates the image the next time it loads (an image of another tab is drawn fresh on each load). Browsers and sites may keep a copy for about 30 seconds, and may show it for up to five minutes more while they fetch a fresh one, so a page can show the previous version briefly after an edit.

## Scoping the image to one tab

By default the image shows the project's first tab. When the project has more than one tab, the **Live image** menu also shows a **Tab** dropdown: pick a tab and every copy option (image URL, Markdown, HTML) carries a tab parameter that scopes the image to that tab. That way a README can show the roadmap tab while a team page shows the sprint board, each from its own URL. The choice applies to every pass while the dialog is open.

A pass scoped to [one tab](/help/collaboration/sharing/one-tab/) always shows its own tab, so its menu has no **Tab** dropdown.

## When it is not offered

The **Live image** menu is hidden on every pass while the project has a [share password](/help/collaboration/sharing/share-passwords/). An `<img>` request cannot supply a password, so the server refuses an image for a protected project rather than leak it, and offering the option would only mislead. That includes image URLs you copied before setting the password: they stop showing the project. Remove the password to use a live image, or use the [embed](/help/collaboration/sharing/embeds/), which can prompt for the password inside its frame.

A live image also stops working when its share link is revoked or [expires](/help/collaboration/sharing/share-link-expiry/), so keep the link alive for as long as the image is in use.

## Privacy

A live image only exposes what its share link exposes, as a flat picture with no editing actions.
