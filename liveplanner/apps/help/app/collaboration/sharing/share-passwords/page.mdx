A share password is an optional password on a project. When it is set, anyone opening any share link for that project must enter the password before they can see it. It is there to stop people guessing or stumbling onto a share URL, not to provide strong encryption.

## How it works

The password belongs to the **project**, not to a single link. One password covers every share link you create for that project, [embeds](/help/collaboration/sharing/embeds/) included. Once a visitor enters it correctly, it stays in effect for their whole visit, so their reads, edits, images, and realtime all stay authorised.

As the owner you always bypass the password. So do members of the [team](/help/collaboration/teams/) whose library holds the project, since they don't come in through a link. The prompt only ever appears for people coming in through a share link.

## Setting a password

<Step n={1}>Open the **Share** dialog on your project.</Step>
<Step n={2}>Switch on **Password Protection** beneath the list of passes.</Step>
<Step n={3}>
  Type a password in the field that appears and choose **Save** (or press **Enter**). The field
  shows what you type, so you can check it.
</Step>

Once saved, the row shows **Password Set** with **Replace** and **Remove**, and every pass gains a small **Password** tag. liveplanner keeps only a scrambled form of the password, so nobody can read it back afterwards, you included: note it down before you save, and use **Replace** to choose a new one if you lose it.

</Figure>

## Changing or removing it

- **Replace** brings back an empty field. Type the new password and choose **Save**, or **Cancel** (or **Esc**) to keep the old one.
- **Remove**, or switching **Password Protection** off, takes the password away at once. Every link then opens without one again.

Setting or replacing a password sends everyone currently in the project through a share link back to the prompt straight away, so they need the new password to carry on. Removing it disconnects nobody.

## What visitors see

When someone opens a protected share link, they get a full-screen card headed **This project is password-protected**, with a single password box and an **Open project** button, instead of the project. A wrong password shows "That password didn't match. Try again." and lets them try again. Guesses are rate-limited per network, so a password can't be found by trying thousands of them.

<Figure caption="A visitor on a protected link sees the password card instead of the project.">
  <SharePasswordGate />
</Figure>

The browser remembers a password that worked, for that link, so a visitor isn't asked again next time. They are asked again only if you replace the password (or remove it and later set a new one), or they clear their browser's site data.

Embedded projects behave the same way: the password prompt appears inside the embed frame. Because browsers keep each site's storage separate, a visitor enters the password once per site where the project is embedded.

## What a password turns off

- **Live images.** An image tag can't supply a password, so the **Live image** menu disappears from every pass while a password is set. See [Live Image](/help/collaboration/sharing/live-image/).

<Tip>
  Pair a password with a [share link expiry](/help/collaboration/sharing/share-link-expiry/) for a
  link that both needs a secret and stops working after a set time.
</Tip>
