# Palette

Follow the references below only as needed; never upfront.

liveplanner shows no palette ([Plan mode](../026-plan/plan-mode.md#no-palette)). These specs hold the catalogues and
presets the model and the element menu still use: the icon and technology marks an element can carry, stickers,
emoji glyphs, the style presets of the element menu's Presets category, and the Behaviours family.

- ./technology-icons.md - when working on Technology icons: Technology palette category: full-colour AWS / Azure / generic-infra brand icons for architecture diagrams
- ./style-presets.md - when working on Style presets: One-click Presets category: theme colour + border variations for shapes, animated line styles for arrows
- ./emoji-icons.md - when working on emoji icon entries: the `text` prim, its two renderers, and why an emoji needs no special casing
- ./palette-category-browse.md - when working on Browsing the palette by category: The Icons and Technology tabs browse by category tile with a breadcrumb, the same drill-in the Tools tab uses, replacing their category / provider filter dropdowns; search always runs over the whole catalogue
- ./palette-top-level-categories.md - when working on the Behaviours family: which shape kinds collect what the room thinks or act when pressed, what a Participant may write on, and which carry their own `…`
- ./stickers.md - when working on the sticker shape kind: why it is not an icon, its self-coloured art, rotation on entry and its ids
- ./build-category.md - when working on The Build palette category: A Common-band palette category for the elements that HOLD other work: mind node, lane, frame, table (the timeline moved to Concepts). They were filed by what they look like and scattered across Write / Draw / Data / Components; what groups them is the moment you reach for them, which is when you are deciding how the canvas is arranged. Tile ids unchanged, so saved Favourites survive the move
