# Explorer structure

The Explorer's sidebar and pages are the shared package's. Its views are Home, My Work, Unsorted, Recent, Favourites, Shared With Me, Trash, Inbox, Timeline, Search, a folder and a team's library, at `/explorer/<view>` ([its README](../../../../packages/explorer/README.md) "Views"). There are no Tags or Themes views. liveplanner has no Explorer sidebar or drawer of its own.

The Explorer is liveworkspace's, built once for every app and shown at liveplanner.app's own `/explorer` ([one-explorer.md](../../../../liveworkspace/docs/one-explorer.md) "The Explorer on each app's address"): liveplanner's router serves liveworkspace's page there with the address unchanged ([router-app.md](../016-platform/router-app.md) "The Explorer on liveplanner.app"). It opens filtered to plans, in liveplanner's colours, with liveplanner's logo after liveworkspace's in its header, and it signs in as liveplanner's own session. liveplanner's Explorer links (the header's Explorer button, the editor's brand menu, the panel's Open Page) are same-origin `/explorer` addresses (`apps/editor/lib/explorer-href.ts`). Items, New (`/new`, filed where it was pressed), share links and help stay on liveplanner.app. The editor's floating Explorer panel is the package's `ExplorerPanel`, inside liveplanner (`apps/editor/app/embed/workbench/ExplorerHost.tsx`).

Old addresses keep working, mapped by the page itself: `/explorer/profile` and `/explorer?settings=notifications` (every notification email's unsubscribe link, [profile-and-email-notifications.md](../014-identity/profile-and-email-notifications.md)) open notification settings in place, `/explorer/activity` the Inbox, `/explorer/dynamic` My Work, `/explorer/generated` the Made by AI filter, `/explorer/invites` the account's teams on liveworkspace.app, and `/explorer/offline` This Browser.

This Browser (plans kept only in this browser) is in the Explorer on liveplanner.app, which can read this browser's storage there: the offline store keeps a small list of them (id, name and dates; `apps/editor/lib/offline/this-browser.ts`), and the Explorer shows a This Browser row with their count, its own view at `/explorer/offline`, a This Browser group in the Trash and the opened ones in Home's Jump Back In, each opening in the editor; signed in, each live row has **Sync Plan**, and each plan's menu has **Take Offline**. Both hand over to the This Browser page (`/offline?convert=take-offline|sync&item=<id>`), which checks the plan is the person's to move, asks them to confirm, and runs the move (`apps/editor/hooks/persistence/useConversionHandoff.ts`, over the shared `@liveworkspace/explorer/conversion-handoff`). `/offline` lists them too, with Sync Plan on each row for a signed-in person, and the panel's footer shows a This Browser row while there are any. The Explorer on liveworkspace.app, which can't read it, links to `/offline`.

The plan is [one-explorer.md](../../../../liveworkspace/docs/one-explorer.md); the calls and types are in [one-explorer-contracts.md](../../../../liveworkspace/docs/one-explorer-contracts.md) "Items". The Explorer that shows it is the shared package, [`@liveworkspace/explorer`](../../../../packages/explorer/README.md).
