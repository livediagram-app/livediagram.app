# Explorer structure

The Explorer's sidebar and pages are the shared package's. Its views are Home, My Work, Recent, Favourites, Shared With Me, Trash, Inbox, Timeline, Search, a folder and a team's library, at `/explorer/<view>` ([its README](../../../../packages/explorer/README.md) "Views"). There are no Tags or Themes views, and no Unsorted view: a plan in no folder sits at the root of My Work, or of its team, which lists it. liveplanner has no Explorer sidebar or drawer of its own.

The Explorer is liveworkspace's, built once for every app and shown at liveplanner.app's own `/explorer` ([one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md) "The Explorer on each app's address"): liveplanner's router serves liveworkspace's page there with the address unchanged ([router-app.md](../016-platform/router-app.md) "The Explorer on liveplanner.app"). It opens filtered to plans, in liveplanner's colours, with liveplanner's logo after liveworkspace's in its header, and it signs in as liveplanner's own session. liveplanner's Explorer links (the header's Explorer button, the editor's brand menu, the panel's Home See all) are same-origin `/explorer` addresses (`../packages/workbench/src/lib/explorer-href.ts`). Items, New (`/new`, filed where it was pressed), share links and help stay on liveplanner.app, and so do the kinds Home's hero pictures (Board, Sheet, Dashboard, Form), each starting its template through `/new?template=` ([one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md) "What you can make, on Home's hero"). The editor's floating Explorer panel is the package's `ExplorerPanel`, inside liveplanner (`apps/editor/app/embed/workbench/ExplorerHost.tsx`). Its Current card shows the open plan on top, from the index (the package's `useOpenItem`) or, for a plan kept only in this browser, from This Browser's list with the This Browser pill and This Browser's menu; on a desktop or tablet the popover is up to 60rem wide and 56rem tall, inside the window, over a dimmed scrim on every screen size (a press on it closes the panel and focus goes back to the menu button), and on a phone it stays the sheet ([one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md#the-explorer-on-each-apps-address) "The Explorer on each app's address": the editors' panel).

Old addresses keep working, mapped by the page itself: `/explorer/profile` and `/explorer?settings=notifications` (every notification email's unsubscribe link, [profile-and-email-notifications.md](../014-identity/profile-and-email-notifications.md)) open notification settings in place, `/explorer/activity` the Inbox, `/explorer/unsorted` and `/explorer/dynamic` My Work, `/explorer/generated` the Made by AI filter, `/explorer/invites` the account's teams on liveworkspace.app, and `/explorer/offline` This Browser.

This Browser (plans kept only in this browser) is in the Explorer on liveplanner.app, which can read this browser's storage there: the offline store keeps a small list of them (id, name and dates; `apps/editor/lib/offline/this-browser.ts`), and the Explorer shows a This Browser row with their count, its own view at `/explorer/offline`, a This Browser group in the Trash and the opened ones in Home's Jump Back In (each a card like the rest with the This Browser badge, its menu and its drag to the Trash or a folder, [one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md) "This Browser in Jump Back In"), each opening in the editor; signed in, each live row has **Sync Plan**, every live row has **Delete** (asked first), and each plan's menu has **Take Offline**. Both hand over to the editor at the plan's own address (`/project/<id>?convert=take-offline|sync|delete&item=<id>`), which checks the plan is the person's to move, asks them to confirm, and runs the move (`apps/editor/components/dialogs/ConversionHandoff.tsx` over `apps/editor/hooks/persistence/useConversionHandoff.ts` and the shared `@liveworkspace/explorer/conversion-handoff`). The editor's Explorer panel has This Browser as a view of its own: a rail entry under More with the count, shown while there are any, opening its pane in place, each plan opening in the editor and, signed in, with Sync Plan run in place (`apps/editor/hooks/persistence/useThisBrowserHost.ts`). `/offline`, the old This Browser page, only redirects to `/explorer/offline`, its query kept. The Explorer on liveworkspace.app, which can't read it, links to `/explorer/offline` here.

The plan is [one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md); the calls and types are in [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Items". The Explorer that shows it is the shared package, [`@liveworkspace/explorer`](../../../../packages/explorer/README.md).
