# Trash

**Moved to liveworkspace's index (October 2026).** The Trash is the index's. Deleting a plan moves it to the Trash for 30 days, restorable to its folder, and the index's daily sweep purges it after that, telling liveplanner to delete the plan's content. A trashed item is reached only by its owner and team, so a share link to it grants nothing. The shared Explorer's Trash view offers Restore, Delete Forever and Empty Trash. liveplanner's trash columns, its local Trash and its daily purge are gone.

Deleting the plan open in the editor leaves for the Explorer on liveworkspace.app (`?trashed=<id>&title=`), which says so once and offers Undo. Moving the plan open in the editor to Archived (from the Explorer panel's menus or Change Folder's Archived) leaves for the Explorer the same way (`?archived=<id>&title=`), since an archived plan is closed: it says "Moved “<name>” to Archived." once, with no Undo (`leaveArchivedItem`, [one-explorer.md "Archiving the open item"](../../../../liveworkspace/docs/specs/004-index/one-explorer.md#archived)). Archiving any other plan keeps the editor open. An editor left open on a plan that was trashed has its saves refused (410 `project_trashed`) and shows the deleted state. The same 410 answers every REST and MCP call on a trashed plan, an API token's included: the room refuses a token's grant cached from before the trash on the next call ([one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Where an item stands", Work Tracker 1323), and an archived plan's with `409 archived`. API clients can still list, restore and delete trashed plans at `/api/trash` ([API](../015-api/api.md)), which reads and writes the index.

The plan is [one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md); the calls and types are in [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Items". The Explorer that shows it is the shared package, [`@liveworkspace/explorer`](../../../../packages/explorer/README.md).

## Open editors

A trash made anywhere (the editor, the Explorer, the REST API, MCP `delete_project`) is the index's: it tells liveplanner where the plan now stands (`POST /api/internal/items/:id/standing`, one-explorer-contracts.md "Where an item stands") off the trash's own path, and the api hands it to the plan's room (`takeStanding`, Work Tracker 1141). When that word is `trashed: true` and newer than the last one the room kept, the room sends `{kind: 'project-trashed'}` from `system` to every session, closes each socket with 4004 (`PROJECT_TRASHED_CLOSE`) and clears the agents' presence, as it does for a `project-trashed` op on its `/broadcast`. Open editors show the deleted state at once, and MCP live views and the CLI's room streams end. An older or repeated word closes nothing. A newer word that the plan was archived (`archived: true`, not trashed; another tab, the Explorer, MCP `archive_project`, the CLI) closes every socket with 4010 (`ITEM_ARCHIVED_CLOSE`, reason `item-archived`, Work Tracker 1242), sending nothing first, since an archived plan is its owner's alone: each editor stops without reconnecting and leaves for the Explorer (`leaveArchivedElsewhere`), the owner's with "Moved “<name>” to Archived." and anyone else's with "That plan was archived by its owner, so it is no longer open to you."; an MCP live view says "This plan was archived." and the CLI's room stream ends. A move between folders, a move out of Archived and a restore close nothing. The room keeps nothing of it beyond the plan's standing (its schedules stop while it is put away), so a restore reopens as before: the next join is admitted by its grant like any other.
