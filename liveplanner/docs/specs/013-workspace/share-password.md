# Share password

**Moved to liveworkspace's index (October 2026).** A plan's share password is the index's: one password guards every link to the item (`PUT /items/:id/share-password`), set, changed or removed in the shared Share dialog. liveplanner's password columns, its hashing and its password routes are gone.

What liveplanner still does is ask for it. A link visitor whose link needs a password sees the password gate (`../packages/workbench/src/components/dialogs/SharePasswordGate.tsx`, in this product's word through `apps/editor/components/dialogs/SharePasswordGate.tsx`); the password is kept for the tab's session and sent with the share code (`X-Share-Code`, `X-Share-Password`) when the editor asks the index for a grant. The index answers 401 `password_required` or 403 `password_invalid`, and the gate says which.

**Reopened by its own address.** A visitor who opened the plan through a password-protected link and reopens it by its own address (`/project/<id>`, from Shared with me, Recent or a bookmark) sends no code. The index's grant refusal then names the link (`401 password_required` with `link`, [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Reopened without the code"), and `openOwnAddress` (`@liveworkspace/workbench/lib/editor-arrival`) opens the plan through that link: the password this browser remembers under its code opens it straight away, and with none (or a changed one) the password gate shows, never Not Found. The address stays the plan's own; the visitor opens at the link's level and tab, carrying its code.

The plan is [one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md); the calls and types are in [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Sharing and access". The Explorer that shows it is the shared package, [`@liveworkspace/explorer`](../../../../packages/explorer/README.md).
