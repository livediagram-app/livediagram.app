# Elements

Follow the references below only as needed; never upfront.

- ./images.md - when working on Image element + per-owner gallery: Image element + per-owner R2-backed gallery with dedupe, the `image_refs` reference index and unused-image retention
- ./blueprints/README.md - when implementing or changing an element from its blueprint
- ./annotations.md - when working on Annotations: Palette marker (themed circle + note glyph): hover to read its note, click to edit
- ./link-cards.md - when working on Link cards: Bookmark element: URL via the element link, server-side unfurl for title/favicon/OG image
- ./progress.md - when working on Progress elements: Horizontal bar + donut ring shapes showing a 0–100 percentage, with fill animations (fill/pulse/stripes)
- ./shape-markers.md - when working on Shape markers: Status glyph inside a shape (traffic-light dots + checkbox), left of the label; Markers context-menu band
- ./timeline-rail.md - when reading how the old Timeline rail became the Timeline concept graphic, or the composite-component pattern it set
- ./rating.md - when working on Rating: 1–5 star rating element with a Rating context-menu category (score picker + star-specific animations)
- ./pie-chart.md - when working on Data charts (pie + bar + line): Data palette category + pie chart element: editable label/value rows + chart-specific slice animations
- ./code-block.md - when working on Code block: Monospace syntax-highlighted snippet as a `code-block` data shape (`code` + `codeLanguage` fields): fixed dark editor-card identity, lazy hand-rolled tokenizer chunk (10 languages), double-click Edit code dialog + context-menu Code section; headless render is plain mono
- ./checklist.md - when working on Checklist: Checkable to-do rows as a `checklist` data shape (`checklistItems`): themed card, on-canvas box toggling (rating-style, edit-role gated, undoable), row editing via a context-menu Checklist section, done-count footer
- ./rich-text-notes.md - when working on Rich-text notes: The per-element note becomes a small rich-text document: a 416px popover with an always-visible toolbar (bold / italic / underline, heading + subheading, bullet / numbered lists, links), stored as `noteRich` runs beside the unchanged `note` plain-text mirror, reusing the label runs model so no HTML is ever stored or rendered
- ./page-element.md - when working on The Page element: A paper-proportioned Page in Tools → Write: white sheet, hairline border, soft shadow, turned-back bottom-right corner, wide margin and top-left body text, written with the existing rich-text editor. A shape kind (`page`) rather than a new element type, exempt from the theme colour projection so it stays paper
- ./block-type-picker.md - when working on The block-type picker: One dropdown in both rich-text toolbars (Paragraph / Heading 1-3 / Bullet point / Numbered point) replacing the separate heading + list buttons, so heading level and list style read as the single decision a writer actually makes
- ./mode-button.md - when working on Selection Mode button: A fixed-size canvas element that looks like a real button — square tile, glyph over "Switch to Avatar", hover + press states — and switches whoever presses it into a selection mode. Press it again while in that mode to go back to the previous one; an Avatar button spawns the character at the button. A `mode-button` shape kind carrying a `mode` field, in the palette's Behaviour group; it stays pressable inside the pointer-inert Avatar / Spotlight / Isometric layers, so a control bar is not a one-way door
- ./portal-element.md - when working on Portal element: A ring of energy linked to another portal, on this tab or any other: click it, or walk an Avatar-mode character into it, and the camera (and character) come out the far side. A `portal` shape kind carrying `portalTarget`, self-painted and aspect-locked, two-way by design, numbered positionally with a menu-only name, inert-and-explains-itself while unlinked; walk-ins fire once on arrival and the portal you came out of is ignored until you step off it
- ./reveal-zone.md - when working on Reveal zone: A frosted cover over part of the canvas. Click it to uncover it on your own screen (local, ephemeral); `revealed` on the element takes it off for everyone. Explicitly NOT a permission — the content underneath is still in the document, the export, and the API
- ./youtube-video.md - when working on YouTube video element: A 16:9 Video element in the Media category: a YouTube poster frame that plays inline. The URL lives in the normal element `link` and the id is parsed on render, never stored; the iframe mounts only on play, on the no-cookie origin, and is pointer-inert so the canvas stays draggable
- ./mind-node.md - when working on The mind node: A node that knows its parent: Tab adds a child to its right, Enter a sibling below, each connected, selected and ready to type into — so a branch is built from the keyboard. `mindParentId` on the shape; the connectors are ordinary pinned arrows
- ./flowchart.md - when working on The flowchart: Steps grown with Tab (next step) and Enter (parallel step), typed in the classic ISO 5807 set (Start / End, Process, Decision, Input / Output, Document, Database, Preparation, Connector) and laid out again after every structural change by the layered layout, first step pinned. `flowchartId`, `flowDirection` and `flowLaneId` on ordinary shapes; connectors are pinned arrows, so merges and loops work; Decisions label exits Yes / No; optional swimlanes are chart-owned Lanes
- ./lane.md - when working on The lane: A titled horizontal band for swimlane diagrams; dragging it carries its contents, reusing the frame's containment predicate rather than a second copy. Replaces the swimlane template's stack of frames, whose borders doubled up and whose titles needed separate gutter cells
- ./sankey.md - when working on the Sankey diagram: A Build element showing how much moves where, bands as wide as the amount they carry. One `sankey` shape kind holding `sankeyFlows` by node name, laid out by a pure link-aware column layout shared by canvas and export; hover readouts, a Flows dialog (table, text, paste, CSV, node rename, live preview, balance notes), node colours, band colouring, layout, labels, unit, Grow / Flow animations; Editor-only edits
- ./entity.md - when working on The entity: a title bar over fields with keys (PK, FK, UK), edited in place, joined field to field by relationships with crow's-foot cardinality, grown with Add Related Entity; one element for the ER table and the UML class box
- ./embed-providers.md - when working on More than YouTube: The video element embeds Vimeo, Loom, Figma and Google Docs / Sheets / Slides as well. The provider is derived from the link rather than stored; only YouTube publishes a poster, so the rest show a named card with a Load button — nothing third-party loads until asked
- ./chair.md - when working on Chair: A Behaviour element an Avatar-mode character sits down in on arrival: seated pose, snap to the seat, walk targets ignored until they stand. Occupancy rides the `avatar` presence op and never touches the document, so a chair can't be left stuck by someone who disconnected. Also the Desk (sit facing a computer) and the two-seater Sofa (sit on the nearer cushion)
- ./office.md - when working on the virtual office pieces: Room (walls that block, a doorway, a name plate), Meeting Table (six seats facing it), Plant and Bookshelf (scenery that blocks), Water Cooler and Coffee Machine (walk up for a drink your character holds, seen by everyone), and Rug
- ./fence.md - when working on Fence: A Behaviour element an Avatar-mode character cannot walk through. One straight run of posts and rails along the element's longer side; fences joined end to end make a barrier of any shape, and gaps narrower than a character are sealed. Blocking runs on each owner's machine and never touches the document; a walk into a fence slides along it
- ./website-embed.md - when working on The Website embed: An Embed provider that frames ANY https address on the canvas, alongside the named services. A last-resort catch-all in embedTargetFor: named providers still win their own hosts, a malformed link for a host we know still errors rather than framing its 404, and javascript:/data: are refused before it. Sandboxed without allow-top-navigation, so a framed page cannot navigate the editor tab
- ./avatar-pad.md - when working on the Avatar Pad: A Behaviour element, a pixel-art teleport platform in the avatar sprite's palette, where everyone entering Avatar mode starts (the nearest pad to the view when there are several, over a Selection Mode button's spawn), arriving in a beam in their own colour that everyone sees, derived from presence; a floor piece, never blocking, Editor-placed
- ./reaction-pad.md - when working on The Reaction Pad: A Behaviour element that throws a burst when pressed OR walked onto in Avatar mode: confetti, sparkles, hearts, applause, fireworks, switched from its menu. Local-first and never state: the room op sits in the never-logged set, carries the element id rather than coordinates, and a burst you missed is a burst that is over
- ./web-components-and-no-groups.md - when working on Web components are elements; groups are gone: Banner, Callout, Stat row, Process steps and Header become single shape kinds that lay themselves out as they resize (shared pure layouts for canvas + export), the Hero becomes an image with a caption card, and every line edits in place. Then groups go entirely: no `groupId`, Group / Ungroup, group mode, drill-in, group quick-connect or `pinned-group` ends; stored documents are migrated on read
- ./card.md - when working on The card: One diagram node with slots (header band, media badge / tile / initial, title, meta line, body label, up to six tags) laid out by a pure `cardLayout`; the Callout becomes its preset and stored callouts migrate to cards on read
- ./badge.md - when working on The badge or attachment: A small text pill in five looks that stands alone or attaches to one of eight points on a host, follows it through moves, resizes, deletes and copies, and draws above it; attachment is shared with the step number
- ./step-number.md - when working on The step number: A numbered disc for walkthroughs; new steps take the next number, Renumber Steps orders them by reading order, attaches like a badge, and Play in Order staggers its animation by number
- ./pointer-note.md - when working on The pointer note: A short note joined by a leader line to a tip that attaches to a point on another element, so the note travels with what it is about
- ./tag-colours.md - when working on Tag colours: A tab-level map from a card tag to a colour; mapped cards take it as their accent edge and their tag chips are tinted
- ./diagram-key.md - when working on The diagram key: A legend that lists the tab's line styles and tag colours by itself, with a meaning typed per row
- ./stack.md - when working on The stack: A container that arranges what is dropped into it in a row, column or grid with an even gap, reflows on every change and hugs its contents
- ./org-chart.md - when working on The org chart: A mind map in the Downward flow whose nodes are person nodes (initials, name, role), grown with Tab and Enter
- ./sequence-diagram.md - when working on The sequence diagram: One element holding participants and messages that lays itself out as a UML sequence diagram, edited as rows
- ./boundary.md - when working on The boundary: A titled, tinted, dashed container (Tab / Inset / C4 styles, icon, meta line) whose tint deepens with nesting; a container like frame and lane, animated without moving motions
- ./concept-graphics.md - when working on Concept graphics: Layer stack, Pyramid (pyramid / inverted / funnel) and Cycle as single elements laying out `conceptRows`, an accent ramp, in-place row editing, and the Concept animation set (build / pulse / flow)
- ./tab-window.md - when working on The tab window: an element showing another tab of the document live, zoomed to fit (`tab-window` with `windowTabId`); its states, the tab list, opening the tab, exports drawing the shown tab, no recursion, share roles
