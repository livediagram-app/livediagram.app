# Workspace

Follow the references below only as needed; never upfront.

- ./explorer-structure.md - when working on the Explorer sidebar or the editor's Explorer panel: places vs views, the Overview / Spaces / More groups, page titles that follow the rows, visibility rules, titles vs separators (Minimal chrome), alignment, ARIA tree keyboard model, mobile drawer, Local only documents
- ./folders.md - when working on Folders: Nested folders for documents in the Explorer; documents with no folder sit at the root of their space; deleting a folder moves its contents up to its parent
- ./share-roles.md - when working on what a share link, embed or API token may do: Viewer, Participant, Editor; ownership powers
- ./share-password.md - when working on Share password: Optional per-document password gating share-link view + edit access; the visitor's per-share-code password cache in localStorage
- ./teams.md - when working on Teams: Teams with Admin/Member roles, email invites, Explorer section
- ./embeds.md - when working on Read-only embeds (`/embed`): Iframe-able `/embed` share view + Copy-embed-code in Share
- ./workbench-embeds.md - when a developer tool (Spinner, VS Code) frames the editor signed in: workbench tickets and sessions, the origin handshake, workbench messages, the selection reference
- ./tab-scoped-share-links.md - when working on Tab-scoped share links: A share link scoped to one tab; other tabs locked, enforced server-side incl. the room
- ./share-link-expiry.md - when working on Share-link expiry: Optional link lifetime (week/month/6 months); Inactive section
- ./team-shared-documents.md - when working on Team shared documents: Per-team folder tree + documents every joined member can manage
- ./live-image-share.md - when working on Live image share link: Share-link-scoped `<img>`-able SVG at `/api/share/<code>/image.svg`, served from the snapshot cache ([Document SVG snapshots](../006-document/document-snapshots.md))
- ./hide-from-recent.md - when working on Hide a document from Recent: Per-user "Hide from Recent" / "Show in Recent" on the document menu in both Explorer surfaces; stored as capped `recentExcludedIds` in the synced preferences blob ([User preferences](../007-editor/user-preferences.md)), filtered before the cap in both Recent lists and in the sidebar badge count; no badge elsewhere
- ./recent-folder-chip.md - when working on Folder location on Recent rows: Each Explorer > Recent row/card names the folder it lives in and links to it (immediate parent only; `My documents` for the root, team name for team rows, none for shared-with-you); a quiet link rather than a status badge, Explorer page only
- ./favourites.md - when working on Favourite documents: Per-user document stars in their own D1 table (unlimited, unlike the 4 KB preferences blob), a Favourite/Unfavourite toggle in both document menus, and a Favourites view (route only, no sidebar row) aggregating personal + team stars with the [Folder location on Recent rows](recent-folder-chip.md) source chip
- ./folder-content-previews.md - when working on Folder content previews: A folder card in the Explorer card grid previews what's inside: a centred 2x2 mosaic of up to four sheets (document snapshots first, then subfolder glyphs, with a `+N` tile for the overflow) instead of one generic folder icon; reuses the [Document SVG snapshots](../006-document/document-snapshots.md) cached thumbnails and the client-side folder indexes, so no new fetch. Card grid only — the list view keeps its count badge
- ./timeline.md - when working on Timeline (the All activity page, reached from Home): a day-grouped feed of everything that happened across your documents, teams and account, with same-day stacking and an optional calendar month grid. A `timeline_events` + `timeline_event_scopes` pair emitted inline on the api worker's write paths (one event, many recipients), scope-typed so a per-document or per-team feed is later a new scope value, not a migration. Editing coalesces to one event per person per document per day. Guests included, and their history migrates on sign-up. The sidebar's Home row
- ./explorer-home.md - when working on Explorer Home: the landing view, one column of Jump back in (a Within reach set: 4 most used, 4 recent) then What happened
- ./activity-page.md - when working on Activity page: New Explorer section at `/explorer/activity`: every open action assigned to you or by you and every unresolved comment thread you are in, across all documents you can open, each row opening the editor at the element with its popover ready. Backed by a collaboration index (`collab_actions` / `collab_threads`) written in the same D1 batch as every tab write, `owner_aliases` so guest-era identities survive sign-up, and a lazy per-owner backfill. Sidebar badge counts open actions assigned to you.
- ./default-folders.md - when working on Default folders: per-person folders new documents land in by creation intent (Diagrams, Whiteboards, Event Storming boards, Retrospectives, Kanban boards: `mode:*`, `kind:*`, `template:*`), the explicit root, Duplicate beside its source, the intent recorded on the document, the `placement_defaults` table, `/api/placement-defaults`, precedence after explicit placement, dangling defaults skipped and kept, guest migration; the Use as default for menu, the default marker, the wizard pre-selecting the default, Settings > Documents
- ./shape-libraries.md - when working on Shape libraries: named, owner-scoped sets of reusable shapes (draw.io libraries imported, one library per file, never merged), the palette My shapes category, the Explorer Shape libraries page, the `/api/shape-libraries` resource, limits and sign-up migration
- ./trash.md - when working on Trash: every document delete moves it to a 30-day Trash (personal, team, or this-browser for Offline Mode), restorable to its folder, purged by the daily cron; trashed documents leave every list, share links / room / saves answer `document_trashed`; Take Offline and account deletion bypass it
- ./explorer-filters.md - when working on Explorer filters: the lens, one string of words and tokens (`opens-in:` `kind:` `template:` `made-by:ai` `edited:` `people:` `space:`) that chips write and the top-bar search types, with autocomplete, scope versus lens, `?q=` in the URL, the chip row, the field, Search results, and Made by AI replacing the Generated bucket
- ./empty-document-cleanup.md - when working on Empty document clean-up: the daily cron moves a document with no elements or articles in any tab, unsaved for 30 days, to the Trash (marked `empty`, a fresh 30 days there); guest, account and team documents, never Offline Mode
- ./blueprints/README.md - when implementing a workspace spec from its blueprint (trash, empty-document-cleanup, shape libraries, document placement, default folders, folder delete, Explorer structure, filters, Home data and view)
