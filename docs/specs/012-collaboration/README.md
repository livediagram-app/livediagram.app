# Collaboration

Follow the references below only as needed; never upfront.

- ./activity-and-audit.md - when working on Activity and audit log: Per-diagram change log + Activity Panel UI + surgical revert
- ./presentation-mode.md - when working on Presentation mode: Full-screen slide deck of author-picked element sets, each slide from one tab, built and run from a Slide Deck panel
- ./session-tools.md - when working on Session tools (timer + voting): Per-tab facilitator countdown/stopwatch + live dot-voting, synced to every participant
- ./assigned-actions.md - when working on Assigned actions: Implemented: Assign Action tile attaches a named/described action on an element to a teammate (any joined team), optional opt-out email notification, on-element badge + popover (complete/edit/delete), a merged Collaborate Panel listing open/resolved actions + comment threads, and the menu's collaboration band split into Collaborate (actions/comments) + Resources (link/note)
- ./realtime-conflict-resolution.md - when working on Realtime conflict resolution: Robust simultaneous editing: element-level ops derived from the change-log diff, applied by id, so same-tab/different-element edits stop clobbering; plus an ordered Durable Object (per-epoch seq + bounded op log) for convergence + clean reconnect catch-up. D1 stays the system of record. A full field-level CRDT for same-element concurrent edits was scoped and deliberately dropped — the selection lock ([Live app](../007-editor/live-app.md)) already covers that case
- ./live-poll.md - when working on Live poll (ephemeral pulse-check): Ephemeral pulse-check run entirely over the realtime room (never D1, no trace after): three unordered `poll-*` RoomOps, Yes/No, Yes/No/Abstain, multiple choice, 1-5 rating and free-text styles, prompt modal with Skip, live results for the host + anyone who responded, host-only end with clipboard copy; view-role may answer but not start
- ./vote-layer-scope.md - when working on Scoping a vote to one layer: A dot-vote can be scoped to one layer, picked before Start vote (active layer preselected, "All layers" available, hidden on single-layer tabs) and locked for the vote; off-layer elements dim to 0.35 while votable ones get a brand ring, both only while casting is open
- ./resync-without-reload.md - when working on Resync without reloading the page: A shared diagram no longer reloads itself: the realtime room persists its epoch/seq so a hibernation wake stops forcing spurious resyncs, and a genuine resync re-fetches tab content in place (preserving viewport, selection, and undo) instead of calling window.location.reload()
- ./session-button.md - when working on Session button: A canvas button that starts a session tool for the room when pressed: a countdown timer, a dot vote, or a poll written in advance. A `session-button` shape kind carrying a `session` config, sharing the Selection Mode button's face and rules; a view-role visitor sees it inert (starting is edit-role) but can still take part
- ./picker.md - when working on Picker: A card that chooses at random when pressed — one of the people in the room, or one of the options written on it. Spins for a second over a result decided at press time, and writes it to the element so everyone lands on the same answer
- ./participant-responses.md - when working on Per-participant responses: A shared `responses` field recording ONE value per participant, persistently — the primitive under the estimate card and the temperature check. At most one response per person (a re-cast replaces), a string value so consumers can disagree about what an answer is, edit-role only, and deliberately not undoable so one person's Ctrl+Z can't retract another's answer
- ./estimate-card.md - when working on Estimate card: Planning poker on the canvas: pick privately from a fibonacci / t-shirt / powers scale, the room shows WHO has answered but not what, then one Reveal shows every value at once with the spread called out. Clear starts the next round
- ./temperature-check.md - when working on Temperature check: A fist-of-five gauge: everyone registers 1-5 and the element shows the distribution and the average live. Deliberately never hidden — the opposite choice from the estimate card, because watching the bars move IS the reading
- ./idea-box.md - when working on Idea box: Anonymous submissions held until a reveal. Anonymity is structural (the schema is a list of strings with nowhere to put an author) plus two closed leaks: no change-log entry and no selection on add. The wire-level limit is documented, not papered over. Open cards scatter to sticky notes
- ./poll-result-capture.md - when working on Keeping a poll's results: The host's poll panel ends with two buttons: End, or End & keep results, which drops the tallies onto the canvas as an ordinary bar chart. Closes the one cost [Live poll (ephemeral pulse-check)](live-poll.md) accepted that hurt, without reopening the poll's ephemerality or adding an op kind
- ./agenda.md - when working on Agenda: An ordered run of segments with minutes; pressing one starts the tab timer through the same `startTimer` entry point the session button uses and marks the segment current. Total shown in the header, done segments struck through, no auto-advance
- ./decision-record.md - when working on Decision record: A decision on the diagram beside the thing it decided: statement as the label, a status chip (proposed / accepted / rejected / superseded), a date, and the drivers. The chip is tinted, never the element fill, so the theme still owns the box
- ./roll-call.md - when working on Roll call: A card that freezes who was in the room when Take roll was pressed, rather than tracking live presence. Names and colours are COPIED, the opposite of the change log's migration 0013, because minutes are a statement about a past moment
- ./follow-me-viewport.md - when working on Follow-me viewport: Pin your pan / zoom / tab to a peer's over a new ephemeral `viewport` room op. Start from their avatar in the presence stack; any canvas gesture of your own breaks it instantly and silently. Unilateral by design, mutual follows refused, zoom mirrored exactly rather than re-fitted
- ./comment-pin.md - when working on The Comment Panel: A Collaborate card that shows a whole comment thread on the board, so a remark can be about a PLACE rather than whichever shape is nearest — and, attached to an element by an ordinary arrow, can be read by everyone in the export and the session rather than in one reader's popover. No comment machinery of its own: it holds the ordinary commentThread
- ./done-check.md - when working on The Done check: Everyone marks themselves finished; the card shows who has and who has not, and flashes when the last person does. Built on the [Per-participant responses](participant-responses.md) responses primitive with one fixed value, so marking and unmarking are the same call. The waiting list is derived from who is IN the room, so somebody who closed their tab cannot hold it open forever
- ./bring-focus.md - when working on Bring Focus: An element that offers every other person in the room a jump to it, at your zoom, on your tab. The push half of Follow Me ([Follow-me viewport](follow-me-viewport.md)) and the one-off: an invitation pill with Go rather than a yank, because a push arrives unasked in the middle of somebody's work. Carries the element's centre + the presser's zoom rather than their pan, since two people rarely have the same window
- ./collaborator-enhancements.md - when working on Collaborator enhancements: Clicking any avatar in a tab's presence stack opens a Collaborators modal: everyone in the diagram grouped by the tab they are on, with Go to Tab per group and Follow per person (Follow moved here from the avatar click, [Follow-me viewport](follow-me-viewport.md)). Replaces the "+N" overflow popover. Built from the same per-tab presence map as the tab bar so the two cannot disagree
- ./action-panel.md - when working on The Action Panel: A Collaborate card that shows one assigned action on the board (name, description, assignee, status) and is configured from the card through the existing Assign Action dialog. No action machinery of its own: it holds the ordinary `action` field, so the Collaborate panel, Activity page and assignment email all find it unchanged. The action sibling of the Comment panel ([The Comment Panel](comment-pin.md)).
- ./facilitator.md - when working on Facilitator: One person in a live session holds the facilitator baton and the tools that run the room answer to them: timer, votes, polls, reveals, the picker, Bring Focus. Nobody holds it by default and a session that never takes it is unchanged. The room is not told who anybody is ([Public API and API tokens](../015-api/public-api-and-tokens.md) §6), so the baton is held by a server-minted TOKEN the holder presents on hello: unspoofable, survives a refresh, released 90s after they leave, dead when the room empties. The owner can always take it back (one verified `X-Verified-Owner` bit at upgrade). Who is driving, not who is allowed
- ./qa-board.md - when working on Q&A board: A Slido-style Collaborate card: anyone (view links included) adds a note, named or anonymous; everyone upvotes once per note; the list keeps itself sorted and animates as the ranking moves. The facilitator spotlights a note for discussion and folds it into a Discussed drawer when done. The server owns the board: one endpoint (gateRead for add/vote), a compare-and-swap D1 write, a sequenced system `qa` op, server-hashed voter ids, and a `qaRev` that stops stale snapshots rolling it back
- ./collab-race-hardening.md - when working on Collaboration race hardening: Presses on shared cards (done check, estimate, temperature, idea box, checklist, comments, votes) must not be lost, duplicated or retracted when many people act at once. Records the six shared causes a review found and fixes them in phases: collaborative presses leave undo alone and survive it, the save baseline follows remote ops so nothing echoes or cancels a local save, a vote carries a round; then per-participant ops, server-side merge in D1, and the remaining transport gaps
