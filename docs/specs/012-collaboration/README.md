# Collaboration

Follow the references below only as needed; never upfront.

- ./session-tools.md - when working on Session tools (timer + voting): Per-tab countdown/stopwatch + live dot-voting, synced to every participant
- ./assigned-actions.md - when working on Assigned actions: Implemented: Assign Action tile attaches a named/described action on an element to a teammate (any joined team), optional opt-out email notification, on-element badge + popover (complete/edit/delete), a merged Collaborate Panel listing open/resolved actions + comment threads, and the menu's collaboration band split into Collaborate (actions/comments) + Resources (link/note)
- ./realtime-conflict-resolution.md - when working on Realtime conflict resolution: Robust simultaneous editing: element-level ops derived from each commit's before/after diff, applied by id, so same-tab/different-element edits stop clobbering; plus an ordered Durable Object (per-epoch seq + bounded op log) for convergence + clean reconnect catch-up. D1 stays the system of record. A full field-level CRDT for same-element concurrent edits was scoped and deliberately dropped; such edits stay last-writer-wins, made rare by the advisory selection lock ([Live app](../007-editor/live-app.md))
- ./vote-layer-scope.md - when working on Scoping a vote to one layer: A dot-vote can be scoped to one layer, picked before Start vote (active layer preselected, "All layers" available, hidden on single-layer tabs) and locked for the vote; off-layer elements dim to 0.35 while votable ones get a brand ring, both only while casting is open
- ./resync-without-reload.md - when working on Resync without reloading the page: A shared document no longer reloads itself: the realtime room persists its epoch/seq so a hibernation wake stops forcing spurious resyncs, and a genuine resync re-fetches tab content in place (preserving viewport, selection, and undo) instead of calling window.location.reload()
- ./session-button.md - when working on Session button: A canvas button that starts a session tool for the room when pressed: a countdown timer, a stopwatch or a dot vote. A `session-button` shape kind carrying a `session` config, a fixed-size button face; a view-role visitor sees it inert (starting is edit-role) but can still take part
- ./picker.md - when working on Picker: A card that chooses at random when pressed — one of the people in the room, or one of the options written on it. Spins for a second over a result decided at press time, and writes it to the element so everyone lands on the same answer
- ./participant-responses.md - when working on Per-participant responses: A shared `responses` field recording ONE value per participant, persistently — the primitive under the temperature check. At most one response per person (a re-cast replaces), a string value so consumers can disagree about what an answer is, edit-role only, and deliberately not undoable so one person's Ctrl+Z can't retract another's answer
- ./temperature-check.md - when working on Temperature check: A fist-of-five gauge: everyone registers 1-5 and the element shows the distribution and the average live. Deliberately never hidden, because watching the bars move IS the reading
- ./decision-record.md - when working on Decision record: A decision on the diagram beside the thing it decided: statement as the label, a status chip (proposed / accepted / rejected / superseded), a date, and the drivers. The chip is tinted, never the element fill, so the theme still owns the box
- ./comment-pin.md - when working on The Comment Panel: A Collaborate card that shows a whole comment thread on the canvas, so a remark can be about a PLACE rather than whichever shape is nearest — and, attached to an element by an ordinary arrow, can be read by everyone in the export and the session rather than in one reader's popover. No comment machinery of its own: it holds the ordinary commentThread
- ./comment-mentions.md - when working on Comment mentions: `@handle` a teammate from the document's team in a comment; stored as structured `mentions` on the comment, drawn as chips, put on the mentioned person's Inbox, and emailed via the server-verified notify-mention endpoint behind the `notifyMentions` setting
- ./collaborator-enhancements.md - when working on Collaborator enhancements: Clicking any avatar in a tab's presence stack opens a Collaborators modal: everyone in the document grouped by the tab they are on, with Go to Tab per group. Replaces the "+N" overflow popover. Built from the same per-tab presence map as the tab bar so the two cannot disagree
- ./action-panel.md - when working on The Action Panel: A Collaborate card holding a checklist of assigned actions (`actions: ElementAction[]`, read everywhere through `elementActions`), each added, ticked and edited from the card through the existing Assign Action dialog. No action machinery of its own, so the Collaborate panel, Inbox and assignment email find every action unchanged. The action sibling of the Comment panel ([The Comment Panel](comment-pin.md)).
- ./collab-race-hardening.md - when working on Collaboration race hardening: Presses on shared cards (temperature, checklist, comments, votes) must not be lost, duplicated or retracted when many people act at once. Records the six shared causes a review found and fixes them in phases: collaborative presses leave undo alone and survive it, the save baseline follows remote ops so nothing echoes or cancels a local save, a vote carries a round; then per-participant ops, server-side merge in D1, and the remaining transport gaps

## Removed: the Activity panel

The per-tab **Activity panel** (Tab Activity) and the change log behind it, which recorded each undoable commit with its author and offered per-entry Revert and Clear Activity, were removed on 2026-10-03. Its spec (`activity-and-audit.md`) is deleted; git history holds it.

- The `change_log` table is dropped by migration `0064_drop_change_log.sql`; the daily cron no longer sweeps it, the four `/api/documents/:id/log` endpoints are gone from the API and its OpenAPI reference, and the realtime room no longer carries `log` / `log-remove` ops.
- The `activityPanelEnabled` preference and the revert hover preview are retired ([User preferences](../007-editor/user-preferences.md)).
- **Undo and Redo stay, unchanged in behaviour.** They are snapshot-based (`useDocumentHistory`), personal to each editor and session, and sit in the bottom-right cluster and on Cmd/Ctrl+Z, Cmd/Ctrl+Shift+Z and Ctrl+Y. They are no longer paired with any audit entry. A continuous control (a background slider, an element colour or opacity picker) still takes one undo step per burst: the first tick checkpoints and ticks within 500 ms of the last stay in that step (`useBurstCheckpoint`, which inherited the window the log's debounce used to own).
- Document-level history (renames, sharing, theme changes, a daily "worked on") still lives in the [Timeline](../013-workspace/timeline.md); the Explorer's [Inbox](../013-workspace/inbox.md) is unrelated and stays.
- Help: the Activity Panel category is gone; Undo and Redo moved to Canvas, and the old addresses redirect ([Help app](../018-help/help-app.md#renamed-articles)).
