A **changeset** changes a tab with a short list of edit operations, applied together or not at all. This page lists the whole vocabulary: every operation, how to pick the elements it acts on, where new elements go, and what the answer tells you. [Working with Spaces](/help/developers/working-with-documents/#update-a-tab) shows how to send one.

It reaches a tab through the API: `POST /documents/{id}/tabs/{tabId}/changesets` with `"operations"` as a string (the line form) or an array of objects (the JSON form).

## Two Forms

The **line form** is one operation a line, which is what an agent writes most easily. Values with spaces are quoted (`label="Sign in"`), and blank lines and lines starting with `#` are skipped:

```text
# Rename the actions note, add a risks note under it and a plant beside it
set n2 label="Next Steps"
add sticky id=risks label="Risks" below:n2
add plant right-of:risks
```

The **JSON form** is one object an operation, which is what a script produces. Any line of the text form that starts with `{` is read as JSON, so the two mix:

```json
[
  { "op": "set", "target": "n2", "fields": { "label": "Next Steps" } },
  {
    "op": "add",
    "kind": "sticky",
    "id": "risks",
    "fields": { "label": "Risks" },
    "place": { "rel": "below", "ref": "n2" }
  },
  {
    "op": "add",
    "kind": "plant",
    "place": { "rel": "right-of", "ref": "risks" }
  }
]
```

One parser turns the line form into the JSON form, so both are checked the same way. A changeset holds at most **500** operations, and a line at most 16,384 characters.

## Operations

| Operation | Line form                                                               | What it does                                                                 |
| --------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `add`     | `add <kind> [id=<id>] key=value… [<placement>]`                         | Creates an element sized for its label                                       |
| `set`     | `set <selector> key=value… [all]`                                       | Changes only the fields named; `key=` with nothing after it unsets one       |
| `rm`      | `rm <selector> [all]`                                                   | Removes elements                                                             |
| `move`    | `move <selector> <placement> [all]` or `move <selector> by=dx,dy [all]` | Moves elements                                                               |
| `order`   | `order <selector> front`, `back`, `above=<x>` or `below=<x>`            | Changes the stacking order                                                   |
| `layout`  | `layout <selector>`                                                     | Sweeps only the selection into tidy rows, below the elements it leaves alone |
| `test`    | `test <selector> key=value…`                                            | Refuses the whole changeset unless the element still holds these values      |

A few rules hold for every operation:

- **Kinds.** `add` takes `text`, `sticky` or `link-card`, or a Space piece by its kind (`chair`, `desk`, `plant`, `room`, `door` and the rest). A kind livehuddle does not have is refused as `invalid_value`, naming the kinds `add` takes; so are `shape` and the diagram shapes (`square`, `circle`, `diamond` and the rest), which livehuddle no longer supports: add a sticky instead. Images are not made by name; `video`, `table`, `arrow`, `line`, `freehand`, `path` and `annotation` are refused (livehuddle no longer supports them, and a space saved with one keeps it as a placeholder), but an `add` in the JSON form can carry a whole element (`{ "op": "add", "element": { … } }`), which is how an uploaded image goes on a tab.
- **Ids.** `id=` names a new element so later operations in the same changeset can use it. It is a short slug: a lowercase letter, then up to 23 lowercase letters, digits, `-` or `_`. Without one, the element takes the slug of its label (or of its kind, as `sticky`, `sticky-2`).
- **Fields.** `label`, `note`, `shape`, `fill`, `stroke`, `text-color`, `border`, `text` (a size: `sm`, `md`, `lg` or `scale`) and `font` work on the kinds that have them, beside any stored field of the element. `fill=` takes a colour slot of the tab's theme by name (such as `theme`), which follows a theme change; a hex colour works too, with a `colour_overrides_theme` warning. A sticky takes its own colour names instead. A number, `true` or `false` is read as JSON, and a value starting with `[` or `{` is read as JSON as written.
- **Nothing holds.** No element holds others. A lane, stack or boundary saved before livehuddle dropped them is a kind livehuddle does not know: it moves on its own, takes no space when something new is placed, and can be removed.
- **Comments are not fields.** Comment threads and ideas travel live between people, so edit operations never change them; comments have their own [endpoints](/help/developers/agent-comments-presence/).

## Selectors

A selector picks the elements an operation acts on. It is a ref, a quoted label, or `key:value` terms joined by spaces, every one of which must match:

| Selector               | Matches                                                                  |
| ---------------------- | ------------------------------------------------------------------------ |
| `n3`, `146b`, `orders` | The element with that ref, id or unique start of an id                   |
| `"Orders service"`     | The element whose label is exactly that, ignoring case                   |
| `label~orders`         | Elements whose label contains `orders`                                   |
| `type:sticky`          | Elements of that kind, as the outline prints it, or of that element type |
| `shape:chair`          | Shapes of that shape kind                                                |
| `selected`             | What the token's owner has selected in an editor open on that tab        |

Terms combine: `type:sticky label~orders` is the stickies whose label mentions orders.

- A selector must match **exactly one** element unless the operation takes `all`. Nothing matching is refused as `target_not_found` with the nearest labels; several is refused as `target_ambiguous`, listing them.
- `layout` acts on many by nature. Each ref or quoted label you give names one element, and the other terms together add whatever they match.
- `selected` with nothing selected is refused. The owner is whoever the API token belongs to, so an agent can act on "what I have selected" while you point at it.
- The words `selected`, `all`, `front` and `back` are always keywords. Reach an element named one of them by its quoted label or a longer ref.

## Placement

`add` and `move` take one placement.

| Placement      | Puts the element                                                   |
| -------------- | ------------------------------------------------------------------ |
| `right-of:<x>` | To the right of x                                                  |
| `left-of:<x>`  | To the left of x                                                   |
| `above:<x>`    | Above x                                                            |
| `below:<x>`    | Below x                                                            |
| `align:<x>`    | Sharing x's centre, on the axis the element is already nearer      |
| `at:x,y`       | At that point, relative to the tab's content origin                |
| `gap:<n>`      | Beside a side or `align` placement: the space to leave, 0 to 2,000 |

Without a placement, a new element goes beside the last one added, or to the right of everything. A spot already taken moves along the placement's direction until it is free. In the JSON form a placement is `{ "rel": "below", "ref": "n2", "gap": 40 }` or `{ "rel": "at", "x": 0, "y": 200 }`, and `by=dx,dy` is `"by": [dx, dy]`.

What you did not ask to change stays put. `set` moves nothing except a box that grows around its centre to fit a longer label (reported). Only `layout` and a whole-tab `replace` lay out many elements, and only the ones they name.

## Flags

| Flag  | On                  | Means                                                   |
| ----- | ------------------- | ------------------------------------------------------- |
| `all` | `set`, `rm`, `move` | Act on every element the selector matches, not only one |

In the JSON form, a flag is a member set to `true`: `"all"`.

## The Answer

A changeset answers with one line per element, the same for a dry run (`?dryRun=1`) and a write:

```text
~ n3  label "Actions"→"Next Steps"
+ risks  sticky "Risks" @240,240 200×200
» n4 n5 n6  +0,+160 (layout)
rev 41→42 · cs_8k2m4q7d1x · revert: livehuddle changeset revert 3f9c2a71-… cs_8k2m4q7d1x
```

| Mark | Means                                              |
| ---- | -------------------------------------------------- |
| `+`  | Added                                              |
| `~`  | Changed, each field before→after                   |
| `-`  | Removed, with the reason when it went with another |
| `»`  | Moved without being named (by `layout`)            |
| `!`  | A warning                                          |

The last line carries the tab's new revision, the changeset's id and the command that reverts it. A changeset that changes nothing answers `nothing changed`.

**Warnings** do not stop a changeset: `value_coerced`, `label_capped` (a shape's label over 40 characters kept its heading and moved the full text into the note), `colour_overrides_theme`, and `no_base` (sent without a `base` revision).

## Refusals

A refused changeset applies nothing. It names the operation, the code and the way out. Lines that do not parse are all reported together (up to ten), so a batch of typos is fixed in one round:

```text
error target_ambiguous · op 2 · set "Pay" fill=green
  "Pay" matches 3 elements:
    n7  sticky "Pay"
    n9  text "Pay"
    n12 room "Pay"
  hint: use a ref, narrow with type:sticky, or add all
nothing was applied
```

| Code                 | When                                                          |
| -------------------- | ------------------------------------------------------------- |
| `parse_error`        | A line does not parse; names the column and what was expected |
| `unknown_operation`  | The first word is not an operation                            |
| `target_not_found`   | A selector matches nothing                                    |
| `target_ambiguous`   | A selector matches several without `all`                      |
| `unknown_field`      | A field the kind does not have; lists the kind's fields       |
| `invalid_value`      | A value outside what the field takes; lists what it takes     |
| `id_taken`           | An `id=` already in use; suggests a free one                  |
| `test_failed`        | A `test` does not hold; shows expected and actual             |
| `changeset_conflict` | A target changed since the `base` revision you sent           |
| `elements_held`      | Someone has a target selected in the editor                   |
| `invalid_result`     | The result would not be a valid tab                           |
| `too_large`          | Over 500 operations, or the tab's size cap                    |

<Tip>
  Send a changeset with `?dryRun=1` first while you learn the vocabulary: the answer is exactly what
  a write would give, and nothing changes.
</Tip>
