A **repository link** binds a directory in your code repository to canvases in livehuddle. Coding agents look for context by searching the files in front of them, and a diagram that only lives behind a link is invisible to them. Once a repository is linked, they find your diagrams by name, read them as text through the [CLI](/help/developers/cli/), and can change them while you watch.

livehuddle stays the home of every canvas. What the repository holds is a **snapshot** at a known revision, never a second copy you edit in parallel.

## Link a Repository

Run this in the repository (or in one package of a monorepo), signed in to the [CLI](/help/developers/cli/):

```bash
livehuddle link init --folder "Minigames" --level files
```

It writes `livehuddle.toml` beside you. In a terminal, giving neither `--folder` nor `--doc` shows a list of your folders to pick from; in a script it lists them as commands instead. `--doc` links single canvases, and you can repeat it or combine it with a folder. A link file looks like this (the ids are placeholders for your real ones, and `dir` is optional, defaulting to `diagrams`):

```toml
host = "https://livehuddle.app"

[covers]
folder = "fld_8k2m4q"          # this folder and its subfolders
documents = ["doc_3h9x2a"]     # and these documents, wherever they live

[mirror]
level = "files"                # none | index | files
dir = "docs/diagrams"
```

Commit `livehuddle.toml`. It holds ids and settings, never a credential: someone without access to your canvases gains nothing from it.

## Choose How Much Lands in the Repository

| Level   | A sync writes                                              | Good for                                      |
| ------- | ---------------------------------------------------------- | --------------------------------------------- |
| `none`  | Nothing                                                    | Projects that only use the CLI                |
| `index` | `INDEX.md`: every canvas, its tabs and its link            | Agents finding diagrams by name (the default) |
| `files` | `INDEX.md`, plus a snapshot and a text outline per diagram | Reading diagrams offline, in reviews and git  |

At `files`, each canvas gets a `.livehuddle.json` snapshot (one element per line, so a change is a one-line diff) and a `.md` outline that an agent reads at a fraction of the size. The outline opens with a line saying it is generated and linking the canvas.

## Sync

```bash
livehuddle sync              # write what changed
livehuddle sync --watch      # keep the files in step until Ctrl-C
livehuddle sync --dry-run    # print what a sync would do, and write nothing
livehuddle link status       # each document and whether it is in step
livehuddle link ls           # the documents the link covers
```

A sync writes newer snapshots, adds canvases that joined the folder and removes the files of canvases that left it or went to the Trash. Git history keeps what was removed. With `--watch`, the files follow within a moment of each change in the editor. `--dry-run` cannot be combined with `--watch`, since it writes nothing to keep in step.

A snapshot's file name comes from the canvas's name when it is first synced, and then stays put, so renaming or moving a canvas never churns your repository. Instead, a sync names the files whose path would now be different. Run `livehuddle sync --relocate` to move them (with `git mv` inside a git repository). A move never overwrites a file livehuddle did not write: if one is already at the new path, the canvas stays where it is and the sync names that file.

Snapshots are for reading. If a snapshot was changed by hand, the sync leaves it alone and names it, so nothing you wrote is lost; send it back with `livehuddle push <file>`. If a tab you changed also changed in livehuddle since, push refuses that tab as stale and sends the rest. Keep a copy of your change, restore the file (`git checkout -- <file>`, or delete it), sync, then make the change again. A file that git left with conflict markers is held back the same way until you keep one side.

A teammate syncing with their own sign-in only reaches what they can open. A canvas they cannot open stays exactly as committed.

## Several Repositories

A command acts on the nearest `livehuddle.toml` at or above the directory you run it in. In a monorepo with a link per package, add `--all` to `sync`, `link status` or `link ls` to act on every link below the current directory.

A link can cover a team folder, so several repositories can link the same diagrams, or a single repository can hold your diagrams for everything else. Each repository keeps its own snapshot; livehuddle keeps the one canvas.

## Public Repositories

Snapshots are as public as the repository they are committed to. `link init` reminds you when the repository has a remote. Choose `index` or `none` if the diagrams themselves should stay private.
