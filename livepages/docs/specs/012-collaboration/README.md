# Collaboration

Follow the references below only as needed; never upfront.

- ./blueprints/README.md - when implementing a collaboration spec from its blueprint
- ./presentation-mode.md - when working on Presentation mode: Full-screen slide deck of author-picked element sets, each slide from one tab, built and run from a Slide Deck panel
- ./assigned-actions.md - when working on Assigned actions: Implemented: Assign Action tile attaches a named/described action on an element to a teammate (any joined team), optional opt-out email notification, on-element badge + popover (complete/edit/delete), a merged Collaborate Panel listing open/resolved actions + comment threads, and the menu's collaboration band split into Collaborate (actions/comments) + Resources (link/note)
- ./realtime-conflict-resolution.md - when working on Realtime conflict resolution: Robust simultaneous editing: element-level ops derived from each commit's before/after diff, applied by id, so same-tab/different-element edits stop clobbering; plus an ordered Durable Object (per-epoch seq + bounded op log) for convergence + clean reconnect catch-up. D1 stays the system of record. A full field-level CRDT for same-element concurrent edits was scoped and deliberately dropped; such edits stay last-writer-wins, made rare by the advisory selection lock ([Live app](../007-editor/live-app.md))
- ./resync-without-reload.md - when working on Resync without reloading the page: A shared document no longer reloads itself: the realtime room persists its epoch/seq so a hibernation wake stops forcing spurious resyncs, and a genuine resync re-fetches tab content in place (preserving viewport, selection, and undo) instead of calling window.location.reload()
- ./follow-me-viewport.md - when working on Follow-me viewport: Pin your pan / zoom / tab to a peer's over a new ephemeral `viewport` room op. Start from their avatar in the presence stack; any canvas gesture of your own breaks it instantly and silently. Unilateral by design, mutual follows refused, zoom mirrored exactly rather than re-fitted
- ./comment-mentions.md - when working on Comment mentions: `@handle` a teammate from the document's team in a comment; stored as structured `mentions` on the comment, drawn as chips, put on the mentioned person's Inbox, and emailed via the server-verified notify-mention endpoint behind the `notifyMentions` setting
- ./collaborator-enhancements.md - when working on Collaborator enhancements: Clicking any avatar in a tab's presence stack opens a Collaborators modal: everyone in the document grouped by the tab they are on, with Go to Tab per group and Follow per person (Follow moved here from the avatar click, [Follow-me viewport](follow-me-viewport.md)). Replaces the "+N" overflow popover. Built from the same per-tab presence map as the tab bar so the two cannot disagree
- ./collab-race-hardening.md - when working on Collaboration race hardening: Presses several people make on one element (checklist ticks, comments) must not be lost, duplicated or retracted when many people act at once: collaborative presses leave undo alone and survive it, the save baseline follows remote ops, per-element deltas, a ledger the api merges into a save, and the remaining transport gaps
- ./session-tools.md - when working on Session tools (timer + voting): Per-tab facilitator countdown/stopwatch + live dot-voting, synced to every participant
- ./vote-integrity.md - when working on Vote integrity: who one voter is for a REST upvote and a dot on a Plan card; accounts count once, and guests are capped per network
- ./vote-layer-scope.md - when working on Scoping a vote to one layer: A dot-vote can be scoped to one layer, picked before Start vote (active layer preselected, "All layers" available, hidden on single-layer tabs) and locked for the vote; off-layer elements dim to 0.35 while votable ones get a brand ring, both only while casting is open
- ./session-button.md - when working on Session button: A canvas button that starts a session tool for the room when pressed: a countdown timer, a stopwatch or a dot vote. A `session-button` shape kind carrying a `session` config, sharing the Selection Mode button's face and rules; a view-role visitor sees it inert (starting is edit-role) but can still take part
- ./picker.md - when working on Picker: A card that chooses at random when pressed — one of the people in the room, or one of the options written on it. Spins for a second over a result decided at press time, and writes it to the element so everyone lands on the same answer
- ./participant-responses.md - when working on Per-participant responses: A shared `responses` field recording ONE value per participant, persistently — the primitive under the estimate card and the temperature check. At most one response per person (a re-cast replaces), a string value so consumers can disagree about what an answer is, edit-role only, and deliberately not undoable so one person's Ctrl+Z can't retract another's answer
- ./estimate-card.md - when working on Estimate card: Planning poker on the canvas: pick privately from a fibonacci / t-shirt / powers scale, the room shows WHO has answered but not what, then one Reveal shows every value at once with the spread called out. Clear starts the next round
- ./temperature-check.md - when working on Temperature check: A fist-of-five gauge: everyone registers 1-5 and the element shows the distribution and the average live. Deliberately never hidden — the opposite choice from the estimate card, because watching the bars move IS the reading
- ./idea-box.md - when working on Idea box: Anonymous submissions held until a reveal. Anonymity is structural (the schema is a list of strings with nowhere to put an author) plus a closed leak: no selection on add. The wire-level limit is documented, not papered over. Open cards scatter to sticky notes
- ./agenda.md - when working on Agenda: An ordered run of segments with minutes; pressing one starts the tab timer through the same `startTimer` entry point the session button uses and marks the segment current. Total shown in the header, done segments struck through, no auto-advance
- ./decision-record.md - when working on Decision record: A decision on the diagram beside the thing it decided: statement as the label, a status chip (proposed / accepted / rejected / superseded), a date, and the drivers. The chip is tinted, never the element fill, so the theme still owns the box
- ./roll-call.md - when working on Roll call: A card that freezes who was in the room when Take roll was pressed, rather than tracking live presence. Names and colours are COPIED, the opposite of the since-removed change log's migration 0013, because minutes are a statement about a past moment
- ./comment-pin.md - when working on The Comment Panel: A Collaborate card that shows a whole comment thread on the canvas, so a remark can be about a PLACE rather than whichever shape is nearest — and, attached to an element by an ordinary arrow, can be read by everyone in the export and the session rather than in one reader's popover. No comment machinery of its own: it holds the ordinary commentThread
- ./done-check.md - when working on The Done check: Everyone marks themselves finished; the card shows who has and who has not, and flashes when the last person does. Built on the [Per-participant responses](participant-responses.md) responses primitive with one fixed value, so marking and unmarking are the same call. The waiting list is derived from who is IN the room, so somebody who closed their tab cannot hold it open forever
- ./bring-focus.md - when working on Bring Focus: An element that offers every other person in the room a jump to it, on your tab, at their own zoom. The push half of Follow Me ([Follow-me viewport](follow-me-viewport.md)) and the one-off: an invitation dialog (Not now / Take me there) rather than a yank, because a push arrives unasked in the middle of somebody's work. Carries the element's centre rather than the presser's pan, and taking it pans to that centre at your own zoom, since two people rarely have the same window
- ./action-panel.md - when working on The Action Panel: A Collaborate card holding a checklist of assigned actions (`actions: ElementAction[]`, read everywhere through `elementActions`), each added, ticked and edited from the card through the existing Assign Action dialog. No action machinery of its own, so the Collaborate panel, Inbox and assignment email find every action unchanged. The action sibling of the Comment panel ([The Comment Panel](comment-pin.md)).
- ./facilitator.md - when working on Facilitator: One person in a live session holds the facilitator baton and the tools that run the room answer to them: timer, votes, reveals, the picker, Bring Focus. Nobody holds it by default and a session that never takes it is unchanged. The room is not told who anybody is ([Public API and API tokens](../015-api/public-api-and-tokens.md) §6), so the baton is held by a server-minted TOKEN the holder presents on hello: unspoofable, survives a refresh, released 90s after they leave, dead when the room empties. The owner can always take it back (one verified `X-Verified-Owner` bit at upgrade). Who is driving, not who is allowed
