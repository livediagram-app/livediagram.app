# Tab-scoped share links

A share link can open every tab or only one. The link and its tab are the index's (`ShareLink.tabId`, chosen in the shared Share dialog's Opens), and the grant the index issues for that link names the tab (`tab`).

livedocuments enforces it. The api checks a grant's `tab` on every request about the document and the document's room confines the socket to it (`apps/api/src/room-scope.ts`, `apps/api/src/routes/document-grant.ts`): the other tabs are locked in the editor and refused by the server, including in the room. A grant whose tab changes on renewal closes the socket (4005) so it reconnects as what it now is. A tab op's payload keeps to the tab it names: the room drops a whole-tab op whose tab has another id and a `tab-meta` patch that names an id, elements or articles (`apps/api/src/room-op-gate.ts`), and an editor receiving one keeps its tab's own id, so a session can never renumber its tab onto one it cannot reach. A tab's name is structure, like the tabs around it: a scoped editor edits its tab's content but never renames it. The rename route (`PUT /api/documents/:id/tabs/:tabId/name`) refuses a scoped grant with 403, a scoped editor's whole-tab save keeps the tab's stored name, the room drops a scoped session's `tab-meta` that sets or clears `name` and relays its whole `tab` op without a name (`opFromScopedSender`), and a receiving editor keeps its own name when a whole tab arrives without one. Freeing someone's held selection is confined the same way: a scoped session frees a hold only from someone on its own tab.

The document is [one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md); the calls and types are in [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Grants". The Explorer that shows it is the shared package, [`@liveworkspace/explorer`](../../../../packages/explorer/README.md).
