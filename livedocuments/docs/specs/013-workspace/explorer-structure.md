# Explorer structure

The Explorer's sidebar and pages are the shared package's. Its views are Home, My Work, Recent, Favourites, Shared With Me, Trash, Inbox, Timeline, Invites, Search, a folder and a team's library, at `/explorer/<view>` ([its README](../../../../packages/explorer/README.md) "Views"). **Invites** shows in the sidebar only while the reader has an invitation waiting on liveworkspace.app (or is on the Invites view), with their count as its badge; each links there to answer it ([Teams](teams.md#invitations)). There are no Tags or Themes views. There is no Unsorted view: a document in no folder sits at the root of My Work, or of its team, which lists it.

The Explorer page is liveworkspace's, served at livedocuments' own `/explorer` by livedocuments' router ([one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md) "The Explorer on each app's address"): the address bar keeps livedocuments' name, it asks the index as livedocuments' session, wears livedocuments' colours, and opens every document, New and template in livedocuments, the kinds Home's hero pictures (Article, Slide Deck, Infographic, Poster) among them, each starting its template through `/new?template=` ([one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md) "What you can make, on Home's hero"). What is livedocuments' own reaches it through the sites registry (`@liveworkspace/sites` `APP_ITEMS.livedocuments`): its addresses, its Image Gallery (`imagesPath`), and its This Browser page (`offlinePath`, which also runs Take Offline and Sync, `offlineConversions`). Teams are made and run over liveworkspace's account API through the router (`/api/workspace/account`). A workbench's workspace frame keeps its own copy of the Explorer (`apps/editor/app/embed/workbench/ExplorerHost.tsx`), with the addresses, New and teams from `apps/editor/lib/explorer-host.ts`, and no team administration. The editor's floating Explorer panel is the package's `ExplorerPanel` (`apps/editor/components/panels/Explorer.tsx`); its Library holds the Image Gallery, read over livedocuments' own API (`/api/images`, the sites registry's `imagesPath`) with the person's Bearer (`apps/editor/lib/explorer-library.ts`). Its Current card shows the open document on top, from the index (the package's `useOpenItem`) or, for a document kept only in this browser, from This Browser's list with the This Browser pill and This Browser's menu; on a desktop or tablet the popover is up to 64rem (its rail 13rem, its preview cards four across) wide and 56rem tall, inside the window, over a dimmed scrim on every screen size (a press on it closes the panel and focus goes back to the menu button), and on a phone it stays the sheet ([one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md#the-explorer-on-each-apps-address) "The Explorer on each app's address": the editors' panel).

Other addresses lead somewhere too, so links out there keep working. `/explorer/profile` and `/explorer?settings=notifications` open Settings on Notifications in place, and any other `?settings=` opens livedocuments' own settings there: every notification email ever sent carries one as its unsubscribe link ([profile-and-email-notifications.md](../014-identity/profile-and-email-notifications.md)). `/explorer/activity` replaces itself with the Inbox, `/explorer/unsorted` and `/explorer/dynamic` with My Work, `/explorer/generated` with the Made by AI filter (documents the index records with source `ai`), and `/explorer/offline` is the Explorer's own This Browser view. Signed in, the Explorer's bottom bar has a **Settings** button beside Appearance that opens livedocuments' settings in place.

## This Browser

Documents kept only in this browser ([Offline Mode](../006-document/offline-mode.md)) never reach the index. livedocuments keeps a small list of them (id, title and dates, never their content) where the Explorer on its address can read it (`@liveworkspace/explorer/this-browser`), and they are the Explorer's **This Browser** view, in the page (`/explorer/offline`) and the editor's panel alike: every one, newest first, read from this browser alone, each opening in the editor. For a signed-in person each row has **Sync Document**, which moves it to the account and so into the Explorer. With none, the view says so. The editor offers the move prompt after signing in ([auth-and-guest-access.md](../014-identity/auth-and-guest-access.md)). `/offline`, the old This Browser page, only redirects to `/explorer/offline`, its query kept (`@liveworkspace/explorer/offline-redirect`).

- **The Explorer** on livedocuments' address has a **This Browser** sidebar row with their count and a view of its own (`/explorer/offline`), lists them in the Trash and among Jump Back In (each a card like the rest with the This Browser badge, its menu and its drag to the Trash or a folder, [one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md) "This Browser in Jump Back In"), and gives each live row **Sync Document** for a signed-in person and **Delete**, asked first. Each document's menu has **Take Offline**. Both hand over to the editor at the document's own address (`/document/<id>?convert=take-offline|sync|delete&item=<id>`), which checks the document is the person's to move, asks them to confirm, and runs the move (`apps/editor/components/dialogs/ConversionHandoff.tsx` over `apps/editor/hooks/persistence/useConversionHandoff.ts` and the shared `@liveworkspace/explorer/conversion-handoff`).
- **The editor's Explorer panel** (and the workbench's) has This Browser as a view of its own: a rail entry under More with the count, shown only while there are some, opening its pane in place, each document opening in the editor and, signed in, with **Sync Document** run in place (`apps/editor/hooks/persistence/useThisBrowserHost.ts`, the panel's `thisBrowser`).

The document is [one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md); the calls and types are in [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Items". The Explorer that shows it is the shared package, [`@liveworkspace/explorer`](../../../../packages/explorer/README.md).
