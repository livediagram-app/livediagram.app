# Workspace blueprint defaults

One row per default applied where a spec is silent or qualitative.

| #    | Blueprint        | Spec silence                                                         | Default applied                                                                                                                                                                          |
| ---- | ---------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SR1  | share-roles      | What the level field is called in storage and on the wire            | `role` everywhere stored or sent (`share_links.role`, `ShareLink.role`), as today; `level` in code (`AccessLevel`)                                                                       |
| SR2  | share-roles      | Which queue a Participant's content write uses                       | One `tabWriteQueue` per document: every read-modify-write of the same tab rows runs through it, so none race                                                                             |
| SR3  | share-roles      | Who hears a Participant op the rule changed                          | Everyone including the sender, so the sender's screen converges on what was stored; an unchanged op skips the sender as an Editor's does                                                 |
| SR4  | share-roles      | How the server derives an adder key                                  | The first 32 hex characters of SHA-256 over `livedocuments:adder:v1:<documentId>:<ownerId>`: stable per person and document, opaque, unlinkable across documents                         |
| SR5  | share-roles      | What a Participant session without an adder key may do               | Update text, move and recolour; never add or remove, since nothing could later prove the element was theirs                                                                              |
| SR6  | share-roles      | Where an embed's cap to Viewer is applied                            | In the editor (`sessionRole`), as embeds have no identity screen; the room cannot tell an embed from a link holder                                                                       |
| SR7  | share-roles      | Where the pass's role mark sits                                      | A full-width header band across the top of the card (was a `w-24` left stub, which cut the link short), so `PARTICIPANT` fits and the link has the card's width                          |
| SR8  | share-roles      | How the three role cards sit                                         | One per row at every width: three across left each blurb four lines deep and the title under the check                                                                                   |
| SR10 | share-roles      | Whether writing on someone else's text box may resize it             | Yes, only for a text box that sizes to its words (`sizing` set): its width and height follow the words. A Participant never moves or resizes someone else's text box by hand             |
| SR11 | share-roles      | How the stored level admits `participate`                            | A nullable `level` column beside the two-valued `role` (written `view` for a Participant): no table rebuild under `community_posts`' cascade, and an older reader of `role` fails closed |
| SR12 | share-roles      | How many of one socket's writes may wait                             | 64 (`PARTICIPANT_PENDING_MAX`): far above a person's pace, one op per changed element every 600 ms; past it the sender re-hydrates                                                       |
| SR13 | share-roles      | How a held-back gesture is reported                                  | One info toast per 4 s burst (`HELD_BACK_NOTICE_MS`): "As a participant you can add and write, move stickies, and remove what you added."                                                |
| WB2  | workbench-embeds | How long a workbench name may be; whether a later ask renames        | 1 to 40 characters, trimmed; a pending request takes the latest name given; a pairing keeps its request's                                                                                |
| WB3  | workbench-embeds | What "the owner's own access" counts                                 | Ownership and team membership; never a share code; a share-link URL in `workbench open` exits 2                                                                                          |
| WB8  | workbench-embeds | What another credential header beside `lvw_` gets                    | `403 workbench_confined`: a session never borrows a share code's or a guest's access                                                                                                     |
| WB9  | workbench-embeds | How a view session's writes are refused, and which pass              | `403 workbench_read_only` at the choke point; the room-ticket mint and the session's own end pass                                                                                        |
| WB10 | workbench-embeds | Which write budget a session spends                                  | `WRITE_RATE_LIMITER` keyed `workbench:<sessionId>`, apart from its token's agent writes                                                                                                  |
| WB11 | workbench-embeds | What a room matches when access ends; what the page's own end closes | The pairing id, carried by the room ticket, so a socket outlives renewal; the page's own end closes nothing                                                                              |
| WB12 | workbench-embeds | Whether an ended page can be revived by a later ticket               | No: `ended` is terminal; the workbench frames a fresh URL to reconnect                                                                                                                   |
| WB13 | workbench-embeds | What a `hello-ack` with a missing or overlong name gets              | Invalid, ignored and logged; the wait runs on to the deadline                                                                                                                            |
| WB14 | workbench-embeds | Whether a ticket outside the renew window is redeemed                | Yes, as a renewal: a workbench may renew early                                                                                                                                           |
| WB15 | workbench-embeds | Which scheme shows before the first `livedocuments:theme`            | The system's (`setAppearanceOverride('system')` in a workspace frame); the frame's stored Appearance setting is not read                                                                 |
| WB16 | workbench-embeds | How the editor treats a request the allow-list refuses               | Refused locally (`WorkbenchConfinedError`), nothing sent, logged once per route, not a network error                                                                                     |
| WB17 | workbench-embeds | Whether an unchanged selection is sent again                         | No: a settled selection is sent only when its text differs from the last sent                                                                                                            |
| WB18 | workbench-embeds | How `reveal` brings elements into view and outlines them             | The changeset toast's Show and outline, in the person's colour, on the active tab                                                                                                        |
| WB20 | workbench-embeds | In which order selected elements are listed                          | The tab's element order, so the text does not depend on the order of clicks                                                                                                              |
| WB23 | workbench-embeds | Which exit `workbench open` gives a 428                              | 4, mapped by the verb; `exitCodeForStatus` is unchanged (it reads 428 as 1)                                                                                                              |
| WB24 | workbench-embeds | How a workbench reads the pairing URL before the wait ends           | stdout's first line, flushed before waiting: the URL, or `{ status, pairingUrl, expiresAt }` with `--json`                                                                               |
| WB25 | workbench-embeds | When `workbench pair` opens a browser                                | Only when stdout is a terminal; piped, as a workbench runs it, it prints and waits                                                                                                       |
| WB26 | workbench-embeds | Where the new error tokens live                                      | `WORKBENCH_ERROR_CODES` in `packages/api-schema/src/workbench.ts`, as `CHANGESET_ERROR_CODES`                                                                                            |
| WB28 | workbench-embeds | What "empty when none" means for a selection message                 | `count` 0; `reference` still carries the header and `whole tab`, which the chip and the agent need                                                                                       |
| WB31 | workbench-embeds | What the page makes of a room close 4005 (access changed)            | `ended(revoked)`: the owner lost access, and a workbench cannot reload into another path                                                                                                 |
| WB33 | workbench-embeds | The page's loading and refusal copy                                  | "Opening your document…"; "Open this document from your workbench" with "This link works once, for a minute."                                                                            |
| WB34 | workbench-embeds | Where Open in livedocuments sits                                     | The right end of the tab bar, after Search and Settings: a corner of the canvas is where docked panels sit                                                                               |
| WB35 | workbench-embeds | What a token card with no pairings shows                             | Nothing extra: no empty heading                                                                                                                                                          |
| WB36 | workbench-embeds | Whether Unpair asks first, and its words                             | Yes, Revoke's popover: "Unpair <name>? Its open documents stop editing until you allow it again."                                                                                        |
| WB37 | workbench-embeds | How logs name an origin                                              | Its host only                                                                                                                                                                            |
| WB38 | workbench-embeds | When "before the session expires" is; how often to ask again         | Ten minutes before, then every minute until a ticket lands or the session expires                                                                                                        |
| WB44 | workbench-embeds | What `tabId` is when `workbench open` names none                     | `null`; the editor opens the document's first tab                                                                                                                                        |
| WB45 | workbench-embeds | What the waiting CLI polls                                           | The pairing request's status at liveworkspace, at the interval it answers, the requesting token only                                                                                     |
| WB46 | workbench-embeds | How Settings reads a token's pairings                                | `GET /api/workbench/pairings` once, grouped by token in the client; `GET /api/tokens` is unchanged                                                                                       |
| WB47 | workbench-embeds | Which logs beyond the spec's list                                    | None: the spec's Observability list is the whole set                                                                                                                                     |
| WB48 | workbench-embeds | Which error codes the ways a `workbench pair` wait ends carry        | `pairing_declined`, `pairing_expired`, `pairing_gone`, so a workbench reading `--json` stderr tells them apart                                                                           |
| WB51 | workbench-embeds | Whether a workspace session runs teams                               | No, `403 workbench_confined`: each needs a signed-in session, so the token cannot; the frame offers none of them                                                                         |
| WB52 | workbench-embeds | Which folders a workspace ticket may start on                        | The owner's personal folders, and folders of teams they are a joined member of; else `404`                                                                                               |
| WB53 | workbench-embeds | Which credential headers pass beside a workspace session             | `X-Share-Code` and `X-Share-Password`, so a shared document opens by its link; `X-Owner-Id` stays refused                                                                                |
| WB54 | workbench-embeds | Whether a view session lists share links                             | No, `403 workbench_read_only` in both scopes, as for a read-only token: the list carries every code                                                                                      |
| WB55 | workbench-embeds | How ending access finds a workspace session's rooms                  | `noteWorkbenchRoom` tells liveworkspace each document whose room ticket a session mints; ending access calls `workbench-close` on each                                                   |
| WB56 | workbench-embeds | The frame paths of the views the spec does not name                  | `/embed/workbench` + the view's `/explorer/...` path; a document `/embed/workbench/document/<id>[?s=][&tab=]`                                                                            |
| WB57 | workbench-embeds | Where a link the frame cannot hold goes                              | A new tab with `noopener`: help, sign-in and every page outside the Explorer                                                                                                             |
| WB58 | workbench-embeds | What New document makes in the frame, and where                      | The asked template, else a blank, named as `/new` names it; in the asked folder or team, else the place's                                                                                |
| WB59 | workbench-embeds | Where Back sits; what it does with no frame entry before             | The canvas's top-left card, where the Explorer menu button sits; `history.back()` when the frame pushed the document from a view, else Home                                              |
| WB60 | workbench-embeds | What a trashed document says in the workspace frame                  | The toast "That document is in the Trash." over the Explorer it returns to                                                                                                               |
| WB63 | workbench-embeds | When `place` is sent again for the same place                        | Whenever any of its fields changes (a rename, a count, a tab); never twice with the same fields                                                                                          |
| WB65 | workbench-embeds | The workspace frame's opening and refused copy                       | "Opening your workspace…"; "Open your workspace from your workbench", "This link works once, for a minute. …"                                                                            |
| WB67 | workbench-embeds | How Settings names a pairing's scope                                 | "One document at a time" or "Whole workspace"                                                                                                                                            |
