# Collaboration

Follow the references below only as needed; never upfront.

- ./blueprints/README.md - when implementing a collaboration spec from its blueprint
- ./presentation-mode.md - when working on Presentation mode: Full-screen slide deck of author-picked element sets, each slide from one tab, built and run from a Slide Deck panel
- ./speaker-note-cards.md - when working on a slide's speaker notes: note cards (a smaller form of flashcards) written in the title bar and the Slide Deck, flipped through in the presenter view, exported and imported with PowerPoint notes
- ./assigned-actions.md - when working on Assigned actions: Implemented: Assign Action tile attaches a named/described action on an element to a teammate (any joined team), optional opt-out email notification, on-element badge + popover (complete/edit/delete), a merged Collaborate Panel listing open/resolved actions + comment threads, and the menu's collaboration band split into Collaborate (actions/comments) + Resources (link/note)
- ./realtime-conflict-resolution.md - when working on Realtime conflict resolution: Robust simultaneous editing: element-level ops derived from each commit's before/after diff, applied by id, so same-tab/different-element edits stop clobbering; plus an ordered Durable Object (per-epoch seq + bounded op log) for convergence + clean reconnect catch-up. The document's store stays the system of record. A full field-level CRDT for same-element concurrent edits was scoped and deliberately dropped; such edits stay last-writer-wins, made rare by the advisory selection lock ([Editor app](../007-editor/editor-app.md))
- ./resync-without-reload.md - when working on Resync without reloading the page: A shared document never reloads itself: the realtime room persists its epoch/seq so a hibernation wake forces no spurious resync, and a genuine resync re-fetches tab content in place (preserving viewport, selection, and undo) instead of calling window.location.reload()
- ./follow-me-viewport.md - when working on Follow-me viewport: Pin your pan / zoom / tab to a peer's over a new ephemeral `viewport` room op. Start from their avatar in the presence stack; any canvas gesture of your own breaks it instantly and silently. Unilateral by design, mutual follows refused, zoom mirrored exactly rather than re-fitted
- ./comment-mentions.md - when working on Comment mentions: `@handle` a teammate from the document's team in a comment; stored as structured `mentions` on the comment, drawn as chips, put on the mentioned person's Inbox, and emailed by the api when the comment is saved, server-verified against the document's team, behind the `notifyMentions` setting
- ./comment-reactions.md - when working on Comment reactions: six fixed emoji (👍 👎 😄 🎉 ❤️ 👀) on any comment, one each per person, toggled from chips or an in-place tray; who reacted on hover or long press; a `comment-react` delta stamped and ledgered by the room, a Participant's through the comment endpoints; shared component and core across all four products
- ./collaborator-enhancements.md - when working on Collaborator enhancements: Clicking any avatar in a tab's presence stack opens a Collaborators modal: everyone in the document grouped by the tab they are on, with Go to Tab per group and Follow per person (Follow moved here from the avatar click, [Follow-me viewport](follow-me-viewport.md)). Replaces the "+N" overflow popover. Built from the same per-tab presence map as the tab bar so the two cannot disagree
- ./collab-race-hardening.md - when working on Collaboration race hardening: Presses several people make on one element (checklist ticks, comments) must not be lost, duplicated or retracted when many people act at once: collaborative presses leave undo alone and survive it, the save baseline follows remote ops, per-element deltas, a ledger the api merges into a save, and the remaining transport gaps
