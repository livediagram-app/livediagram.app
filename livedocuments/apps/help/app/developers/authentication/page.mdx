External API calls authenticate with an **API token**: a long-lived, revocable credential that acts as your account.

## Get a token

Tokens are made on [liveworkspace.app](https://www.liveworkspace.app/explorer?settings=tokens), not through the API. In livedocuments, **Settings**, **Account**, **API Tokens** has a **Manage API Tokens** link there. The secret is shown **once** at creation; copy it then, because it is never displayed again. See [API Tokens](/help/account-and-data/api-tokens/) for the full walkthrough, including the six-month lifetime and the 20-token limit.

Tokens have the form `lwt_` followed by a random string, so they are easy to spot in logs and secret scanners.

[The livedocuments CLI](/help/developers/cli/) can create its own token for you: `livedocuments auth login` signs in through the browser or a device code, then sends that token on every request.

## Send the token

Pass the token in the `Authorization` header as a bearer credential on **every** request. There is no separate login or session step.

```bash
curl https://www.livedocuments.app/api/documents \
  -H "Authorization: Bearer lwt_your_token_here"
```

Every request authenticated this way acts as your account, with the same access to your documents, folders and content that you have in the editor. Account administration (managing teams, creating or listing tokens, deleting the account) needs a signed-in session and is refused to a token. A read-only token (one you created when [connecting an AI tool](/help/account-and-data/connect-ai-mcp/) with **Read-only access** on) can read, and every write is refused except revoking itself and opening or pairing a (view-only) workbench.

## Check or retire the token you are using

`GET /tokens/current` describes the token the request presented: its account, name, whether it is read-only, and when it expires. It is a cheap way for a script to confirm its credential works. `DELETE /tokens/current` revokes that same token, so a script can clean up after itself without you opening Settings.

```bash
curl https://www.livedocuments.app/api/tokens/current \
  -H "Authorization: Bearer lwt_your_token_here"
```

## You need an account

API tokens are a **signed-in-only** feature. The canvas, sharing, and real-time collaboration all stay account-free for guests, but programmatic API access requires [signing in](/help/account-and-data/signing-in/), the same as [teams](/help/collaboration/teams/).

## Tokens versus the guest path

The editor itself does not use an API token. When you are signed in it sends your account's short-lived access token, and when you are not, a [guest](/help/account-and-data/guest-identity/) token that liveworkspace issued to this browser. Those are for the first-party app only: they are not credentials you should build integrations on. For anything outside the editor, use an API token.

## Keep tokens safe

<Note>
  A token has your account's full read and write access to your documents. Treat it like a password:
  keep it out of source control and shared logs, and never put it in client-side code that ships to
  a browser. If a token might have leaked, revoke it on liveworkspace.app and create a replacement.
</Note>

## Errors

A request with no credential, or a bearer that is not an API token, is refused with `400 bad_request` (its message begins `authentication required`); an `lwt_` token that is unknown, expired, or revoked is refused with `401 invalid_token`. See [Errors and Rate Limits](/help/developers/errors-and-rate-limits/) for the status codes and the error response shape.
