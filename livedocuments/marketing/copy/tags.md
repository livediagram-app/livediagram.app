# Tags & keywords

One-word tags for directory listings, app stores, GitHub topics, and Product
Hunt. Ranked by how tightly they fit the product, then split by platform so you
can paste the right set into each field.

Built from [`facts.md`](facts.md). No tag may imply a feature livedocuments
doesn't have (see "Out of scope" there): that means no `diagrams`,
`whiteboard`, `mindmaps`, `flowcharts`, `crdt` or `ai-assistant`.

## Ranked by fit

**Tier 1, core identity (use these first, almost everywhere)**

`documents` · `presentations` · `slides` · `infographics` · `writing` ·
`collaboration` · `multiplayer` · `realtime`

**Tier 2, strong supporting**

`articles` · `posters` · `design` · `opensource` · `free`

**Tier 3, context-dependent (when a directory wants more, or is dev-focused)**

`teamwork` · `collaborative` · `mcp` · `cli` · `mit` · `nextjs` ·
`cloudflare` · `typescript`

## Judgment calls

- **`design`** pulls search traffic but is broad, and livedocuments is not a
  general design tool. Fine as a tag for reach; don't lead with it in prose.
- **Skip** `diagrams`, `whiteboard`, `mindmaps` and `flowcharts`: they were
  livediagram's tags and describe features livedocuments doesn't have.
- Reserve the tech tags (`mcp`, `cli`, `nextjs`, `cloudflare`, `typescript`)
  for developer surfaces (GitHub, dev directories). They mean nothing to a
  general audience.
