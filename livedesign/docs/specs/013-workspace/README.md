# Workspace

Follow the references below only as needed; never upfront.

- ./explorer-structure.md - when working on the Explorer sidebar or the editor's Explorer panel: places vs views, the Overview / Spaces / More groups, page titles that follow the rows, visibility rules, titles vs separators (Minimal chrome), alignment, ARIA tree keyboard model, mobile drawer, designs in This Browser
- ./folders.md - when working on Folders: Nested folders for designs in the Explorer; designs with no folder sit at the root of their space; deleting a folder moves its contents up to its parent
- ./share-roles.md - when working on what a share link, embed or API token may do: Viewer, Participant, Editor; ownership powers
- ./share-password.md - when working on Share password: Optional per-design password gating share-link view + edit access; the visitor's per-share-code password cache in localStorage
- ./teams.md - when working on Teams: Teams with Admin/Member roles, email invites, Explorer section
- ./embeds.md - when working on Read-only embeds (`/embed`): Iframe-able `/embed` share view + Copy-embed-code in Share
- ./workbench-embeds.md - when a developer tool (an agent workbench, VS Code) frames the editor signed in: workbench tickets and sessions, the origin handshake, workbench messages, the selection reference
- ./tab-scoped-share-links.md - when working on Tab-scoped share links: A share link scoped to one tab; other tabs locked, enforced server-side incl. the room
- ./share-link-expiry.md - when working on Share-link expiry: Optional link lifetime (week/month/6 months); Inactive section
- ./team-shared-designs.md - when working on Team shared designs: Per-team folder tree + designs every joined member can manage
- ./live-image-share.md - when working on Live image share link: Share-link-scoped `<img>`-able SVG at `/api/share/<code>/image.svg`, served from the snapshot cache ([Design SVG snapshots](../006-design/design-snapshots.md))
- ./share-link-previews.md - when working on what a pasted share link previews as in Slack, Teams, iMessage and the like: the design's name and a 1200 x 630 PNG share card (`/api/share/<code>/card`, `/api/share/<code>/image.png`), the live worker's head rewrite, and the brand card everywhere else
- ./hide-from-recent.md - when working on Hide a design from Recent: Per-user "Hide from Recent" / "Show in Recent" on the design menu in both Explorer surfaces; stored as capped `recentExcludedIds` in the synced preferences blob ([User preferences](../007-editor/user-preferences.md)), filtered before the cap in both Recent lists and in the sidebar badge count; no badge elsewhere
- ./recent-folder-chip.md - when working on Folder location on Recent rows: Each Explorer > Recent row/card names the folder it lives in and links to it (immediate parent only; `My Work` for the root, team name for team rows, none for shared-with-you); a quiet link rather than a status badge, Explorer page only
- ./tags.md - tags (removed from the Explorer)
- ./favourites.md - when working on Favourite designs: Per-user design stars in the index's own table (unlimited, unlike the 4 KB preferences blob), a Favourite/Unfavourite toggle in both design menus, and a Favourites view (route only, no sidebar row) aggregating personal + team stars with the [Folder location on Recent rows](recent-folder-chip.md) source chip
- ./explorer-details-view.md - when working on the Explorer's Details view: the sortable table (type, comments, access, size, dates), its resting-hover preview, and the per-tab stats behind it (`tab_stats`, `DesignSummary.stats`, the cron backfill)
- ./folder-content-previews.md - when working on Folder content previews: A folder card in the Explorer card grid previews what's inside: a centred 2x2 mosaic of up to four sheets (design snapshots first, then subfolder glyphs, with a `+N` tile for the overflow) instead of one generic folder icon; reuses the [Design SVG snapshots](../006-design/design-snapshots.md) cached thumbnails and the client-side folder indexes, so no new fetch. Card grid only — the list view keeps its count badge
- ./timeline.md - when working on the Timeline (its own Overview sidebar row, also reached from Home): a day-grouped feed of everything that happened across your designs, teams and account, with same-day stacking and an optional calendar month grid. A `timeline_events` + `timeline_event_scopes` pair emitted inline on the api worker's write paths (one event, many recipients), scope-typed so a per-design or per-team feed is later a new scope value, not a migration. Editing coalesces to one event per person per design per day. Guests included, and their history migrates on sign-up. The sidebar's Home row carries its unread badge.
- ./explorer-home.md - when working on Explorer Home: the landing view, one column of Jump Back In (a Within reach set: 4 most used, 4 recent) then What Happened
- ./inbox.md - when working on the Inbox (once called Activity): Explorer section at `/explorer/inbox` (the retired `/explorer/activity` opens it): every open action assigned to you or by you and every unresolved comment thread you are in, across all designs you can open, each row opening the editor at the element with its popover ready. Backed by a collaboration index (`collab_actions` / `collab_threads`) written in the same D1 batch as every tab write, `owner_aliases` so guest-era identities survive sign-up, and a lazy per-owner backfill. Sidebar badge counts open actions assigned to you.
- ./default-folders.md - when working on Default folders: per-person folders new designs land in by creation intent (`mode:*` keys, one per editor mode: `mode:pages`), the explicit root, Duplicate beside its source, the intent recorded on the design, the index's `placement_defaults`, precedence after explicit placement, dangling defaults skipped and kept, guest migration; the Use as Default for menu, the default marker, the wizard pre-selecting the default, Settings > Designs
- ./trash.md - when working on Trash: every design delete moves it to a 30-day Trash (personal, team, or this-browser for Offline Mode), restorable to its folder, purged by the daily cron; trashed designs leave every list, share links / room / saves answer `design_trashed`; Take Offline and account deletion bypass it
- ./explorer-filters.md - when working on Explorer filters: the lens, one string of words and tokens (`opens-in:` `made-by:ai` `edited:` `people:` `space:`) that chips write and the top-bar search types, with autocomplete, scope versus lens, `?q=` in the URL, the chip row, the field, Search results, and Made by AI replacing the Generated bucket
- ./empty-design-cleanup.md - when working on Empty design clean-up: the daily cron moves a design with no elements in any tab, unsaved for 30 days, to the Trash (marked `empty`, a fresh 30 days there); guest, account and team designs, never Offline Mode
- ./blueprints/README.md - when implementing a workspace spec from its blueprint (trash, empty-design-cleanup, design placement, default folders, folder delete, Explorer structure, filters, Home data and view)
