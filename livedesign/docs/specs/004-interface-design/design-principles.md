# Design principles

- **Calm by default**: we make it a great experience without overloading the user; name only what people need to find, and let order, layout and familiar patterns carry the rest.
- **A button always says it can be pressed**: every enabled button, and anything with `role="button"`, shows the pointer cursor on hover, in every app. The rule lives once in the shared theme (`../packages/tailwind-config/theme.css`, base layer), so no control has to remember it; a disabled one keeps the default arrow.
- **One switch**: every on/off switch, in every app, is `@liveworkspace/ui`'s `Switch` (`packages/ui/src/Switch.tsx`): an iOS-style track, brand when on and slate when off, with a white knob. It comes in three sizes: `md` (a 26 x 44 px track, the default, for a row that stands alone such as the start screen's Sync to Server), `sm` (20 x 36 px, for dense rows: Settings, popovers, palette controls, dialogs) and `xs` (16 x 28 px, for a control inside a note or a dark presentation panel). Whatever the size, it keeps a 44 px touch target (`md` by its own box, `sm` and `xs` by the `touch-target` pad, `touch-targets.md`). A row that is itself the control (the whole line flips it) is `SwitchRow`, with the same track drawn inside as a picture, and a chip that flips is `SwitchChip`; both live in the same file. A repo guard in `packages/ui` fails if a `role="switch"` appears anywhere else.
