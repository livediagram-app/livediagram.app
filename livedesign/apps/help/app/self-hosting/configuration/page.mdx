A self-hosted livedesign is configured through environment variables, secrets and each Worker's `wrangler.toml`, not application code. A few `wrangler.toml` values ship with livedesign.app's own settings (the liveworkspace index origin, the KV id, and the MCP issuer and consent URL), so a fork replaces those with its own. Connecting liveworkspace is required, since it signs people in, gives guests their identity and files every design; beyond that, the optional features are genuinely optional: leave them unset and the editor still works, just with less. This page covers how configuration is supplied and the main toggles you will care about.

## How configuration is supplied

Secrets and settings never live in source code, since the repository is public. Instead, each Worker reads them at runtime.

- **Local development** uses a gitignored `.env.local` file per frontend app and a gitignored `.dev.vars` file per Worker.
- **Workers** receive secret values via `wrangler secret put`, and non-secret settings as `[vars]` in the Worker's `wrangler.toml`. Set plain settings in the file rather than the Cloudflare dashboard: every deploy replaces them with what the file declares.
- **Static frontends** only ever bundle values explicitly marked as publishable, prefixed `NEXT_PUBLIC_` so it is obvious they are safe to ship to the browser, and baked in at build time. Server-only secrets stay on the Worker side and never reach client code.

Each app that needs configuration ships an example file designing which variables it expects, so you can see at a glance what to set.

## Sign-in and guests

Everyone who uses livedesign is either signed in to their liveworkspace account or a liveworkspace guest, the same guest in every liveworkspace app. Both identities come from a liveworkspace accounts Worker, so a self-host always connects to one: liveworkspace.app's, or one you run.

1. Register your deployment as an OAuth client of the accounts Worker, with `https://<your-host>/api/auth/callback` as its redirect URI and its own resource.
2. Give the API the accounts Worker's address and your client's details (`ACCOUNTS_URL`, `API_RESOURCE`, `ACCOUNTS_CLIENT_ID`, `ACCOUNTS_CLIENT_SECRET`). The live app always offers sign-in.

Guests need nothing more: the first time a browser needs an identity, the accounts Worker hands it a signed guest token, which the API checks the same way it checks a signed-in person's token. When a guest signs in, their designs move to the account. Accounts unlock the features that need one: [teams](/help/collaboration/teams/), [API tokens](/help/account-and-data/api-tokens/), and, if you set them up, email and the MCP server.

Without the accounts Worker, the API can verify no one, so nobody can create or keep a design.

## The index and images

Where every design is filed, who may open it, share links, folders, Trash and teams all live in liveworkspace's index. The API reaches it at `INDEX_ORIGIN` (a `[vars]` entry in the api `wrangler.toml`, `https://liveworkspace.app` by default) with an `INDEX_KEY` secret, the same value the index holds for livedesign. Uploaded images live in liveworkspace's media service, reached with `MEDIA_KEY` (see the table below). livedesign keeps no database of its own: each design's content lives in its own Durable Object.

## Other optional features

Every other optional feature follows the same pattern: unset means off, and the editor hides what it cannot use.

| Feature                 | Turn it on with                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Image uploads           | `MEDIA_KEY` on the api Worker, its secret on liveworkspace's media service, which keeps the images and their limits (100 images and 100 MB per person). Set `MEDIA_URL` too when the service is not liveworkspace.app's                                                                                                                                                                              |
| Thumbnails              | Create the `livedesign-snapshots` R2 bucket the api `wrangler.toml` already binds (or delete that binding to leave thumbnails off). Photo pages work the same way with the `livedesign-photo-blobs` bucket                                                                                                                                                                                           |
| Email                   | `RESEND_API_KEY` on the api Worker, plus `RESEND_FROM` on a domain verified in Resend and `APP_BASE_URL` set to your origin, since both default to livedesign.app (needs sign-in)                                                                                                                                                                                                                    |
| MCP server for AI tools | Deploy the mcp Worker with its own KV namespace and hostname, then point `CONSENT_BASE_URL` (mcp Worker) at your editor's origin, and `NEXT_PUBLIC_MCP_ORIGIN` (live build) and `OAUTH_ISSUER` (api Worker) at your MCP host (needs sign-in). See [The MCP Server](/help/self-hosting/configuration/mcp-server/)                                                                                     |
| Telemetry               | `TELEMETRY_ENABLED` on the api Worker and `NEXT_PUBLIC_TELEMETRY_ENABLED` on every frontend build, plus a telemetry service of your own that takes the same batches: `TELEMETRY_URL` and the `TELEMETRY_KEY` secret on the api and mcp Workers, and `NEXT_PUBLIC_TELEMETRY_URL` on every frontend build. The hosted service only takes livedesign.app's own events, so without one nothing is stored |
| Workbenches             | Nothing extra beyond sign-in, but set `APP_BASE_URL` on the api Worker to the origin that serves the app, or pairing and frame links point at livedesign.app (needs sign-in)                                                                                                                                                                                                                         |

The `NEXT_PUBLIC_*` values above are baked in at build time. When you deploy through the bundled GitHub Actions workflow, add them to the workflow's build step (or set `mcp_origin` in `deploy.yml`); apart from the sign-in flag, which the workflow turns on when the `ACCOUNTS_CLIENT_ID` repository secret is set, they are not read from repository secrets.
