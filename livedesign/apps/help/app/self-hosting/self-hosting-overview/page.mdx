livedesign is built to be self-hosted, not just used at livedesign.app. Because the whole project is open source, you can clone the repository and run it on your own Cloudflare account. You get every feature in the codebase, no subscription and no licence check. The one service it builds on is liveworkspace, for sign-in, the index where designs are filed, and uploaded images, and you can point it at liveworkspace.app or run your own. This page covers why you might do that and what you are signing up for.

## Why self-host

There are two equally supported ways to use livedesign, and both have the same feature set.

- **Hosted by livedesign** at livedesign.app, free for everyone, a convenience and a public home for the project.
- **Self-hosted**, where you deploy and run it yourself.

You might self-host to keep design data on infrastructure you control, to meet an internal policy, to fork and customise the editor, or simply to run a private instance for your team. Since it is **MIT-licensed**, you are free to modify, embed, or build on it, commercially or not.

## What it runs on

livedesign runs entirely on Cloudflare. The frontends are static (built with Next.js in export mode, so there is no server-side rendering and no Node runtime to operate), and all server-side logic lives in Cloudflare Workers.

- **Cloudflare Workers** serve the apps and host the API.
- **Cloudflare Durable Objects** hold each design: one per design, keeping its content in its own storage and running its real-time room. Each person's workbench has one too.
- **Cloudflare R2** (optional) stores the thumbnails the Explorer shows and photo pages' tiles. The api `wrangler.toml` binds a `livedesign-snapshots` and a `livedesign-photo-blobs` bucket, so create them, or remove a `[[r2_buckets]]` block to run without it. Without snapshots, live images are unavailable and designs show a generic icon in the Explorer; without photo blobs, photo pages are off.
- **liveworkspace** signs people in and gives guests their identity, keeps the index where every design is filed (with sharing, folders, Trash and teams), and runs the media service that keeps uploaded images. The api Worker reaches the index with an `INDEX_KEY` secret and the media service with a `MEDIA_KEY` secret; without `MEDIA_KEY`, image uploads are off and the editor hides the Image element.

This means there is no database to run, no container fleet, and no always-on box to babysit. You deploy Workers and static assets to your Cloudflare account. Durable Objects need the Workers paid plan on that account.

## What you keep control of

A self-hosted instance's servers call only the liveworkspace deployment you point them at. Visitors' browsers still load the editor's fonts from Google Fonts, and image search contacts Openverse when someone uses it.

- **Accounts are liveworkspace's.** People sign in to their liveworkspace account, or use the app as a liveworkspace guest, so the accounts service you connect decides who can use your instance.
- **Telemetry is off by default.** A self-host emits and serves nothing unless you explicitly enable it.
- **Every integration is opt-in.** Email and the MCP server for AI tools each stay off until you set them up. See [Configuration and Optional Auth](/help/self-hosting/configuration/).
- **No license gating.** Nothing phones home to unlock features.
