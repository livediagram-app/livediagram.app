## Domain and naming

| Term           | Identifier                                                                                                    | Meaning                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| App            | `CommunityApp`: `livediagram.app`, `liveplanner.app`, `livedocuments.app`, `livedesign.app`, `livehuddle.app` | The five apps with a Community                                                           |
| Post           | `posts` row; id `newPostId()` (10 characters)                                                                 | One published document, per app                                                          |
| Document       | `posts.document`                                                                                              | The app's document id; opaque, never in a public answer                                  |
| Share code     | `posts.share_code`                                                                                            | The document's community link; the only document handle the public sees                  |
| Owner          | `posts.owner`                                                                                                 | The author's account id in the app; never in a public answer                             |
| Document state | `CommunityDocumentState` `public` / `closed` / `away`                                                         | Where the document stands in its app, as the app last said                               |
| Post state     | `CommunityPostState` `listed` / `hidden`                                                                      | `hidden` after reports, final                                                            |
| Public post    | `PUBLIC_POST` = `app = ? AND state = 'listed' AND document_state = 'public'`                                  | What the public sees                                                                     |
| All Apps post  | `PUBLIC_POST_ANY_APP` = `state = 'listed' AND document_state = 'public'` (`publicWhere('all')`)               | What the Community page's All Apps sees                                                  |
| Own post       | `OWN_POST` = `app = ? AND owner = ? AND document_state <> 'away'`                                             | My Shares (hidden and closed included)                                                   |
| Community key  | `X-Community-Key`, a v4 UUID (`isCommunityKey`)                                                               | A per-browser random key for likes and reports; never an owner id                        |
| Network        | `communityNetwork(ip)`                                                                                        | `a.b.c.0/24` for IPv4 (and IPv4-mapped IPv6), the /56 for IPv6, the raw string otherwise |
| Network hash   | `networkHash(postId, ip)`                                                                                     | First 16 bytes of SHA-256 of `<postId>:<network>`, hex; not comparable across posts      |
| Copier         | `copies.copier`                                                                                               | The app's one-way hash of who copied                                                     |

Categories: each app's own closed set (`COMMUNITY_APP_CATEGORIES[app]`, ids in the spec's "Categories"). An id
two apps share has one label and one type; `CommunityCategory` is the union of every app's ids. Report reasons: `spam`, `offensive`, `personal-info`, `copyright`,
`other`. Sorts: `new`, `loved`, `copied`.

## Behaviour and state

### A post's states

| From                      | Event                                                              | To                               |
| ------------------------- | ------------------------------------------------------------------ | -------------------------------- |
| none                      | `PUT /app/documents/:doc` by an owner under the limit              | listed, `document_state` as sent |
| listed or hidden, owner X | `PUT` by X with `create: true`                                     | same; `409 already_published`    |
| listed, owner X           | `PUT` by X                                                         | listed, details updated          |
| hidden, owner X           | `PUT` by X                                                         | hidden; `409 post_hidden`        |
| any, owner X              | `PUT` by Y (the document changed hands), Y under the limit         | X's post deleted, Y's created    |
| listed, owner X           | `DELETE` by X                                                      | none (cascade)                   |
| hidden                    | `DELETE` by its owner                                              | hidden; `409 post_hidden`        |
| listed                    | `POST /app/sync` (or the sweep) with `away`                        | none (cascade)                   |
| hidden                    | `POST /app/sync` (or the sweep) with `away`                        | hidden, `document_state = away`  |
| any                       | `POST /app/sync` (or the sweep) with `public` or `closed`          | `document_state` set             |
| any                       | `POST /app/sync` (or the sweep) with it in `gone`, or `gone`       | none (cascade)                   |
| any, owner X              | `POST /app/copiers/forget` with `owner: X`                         | none (cascade)                   |
| listed                    | a third report, from 3 distinct keys and 3 distinct network hashes | hidden, `hidden_at = now`        |

### Publish (`publish`), in order

1. JSON body ≤ `MAX_BODY_BYTES` (64 KiB), else `400 invalid_body`.
2. `validateCommunityPostInput(body.input)`: title trimmed and whitespace-collapsed, 3 to 80; description trimmed,
   `\r\n` to `\n`, three or more newlines to two, 20 to 500; one of the app's own categories (`validateCommunityPostInput(input, app)`); tags each normalised
   (`normaliseCommunityTag`: locale-free lowercase then NFC, whitespace and `_` to `-`, only `\p{L}`, `\p{N}`, `-` and
   the `\p{M}` marks that follow a letter or digit, hyphen runs collapsed, 2 to 24 code points; one left-to-right pass,
   no regex over the whole input) and
   de-duplicated, at most 5, any tag failing normalisation fails the field; `anonymous` true unless exactly `false`.
   The first failing field's code: `400 invalid_title` / `invalid_description` / `invalid_category` / `invalid_tags`.
3. `owner` and `shareCode` ids (1 to 200 characters), `documentState` one of three, and an author (`parseAuthor`:
   name trimmed and cut to 80, non-empty; colour `#rrggbb`; picture kept only when `https://` and ≤ 2048), else
   `400 invalid_body`.
4. The document's existing post, if any. Hidden is `409 post_hidden`, whoever owns the document now. Same owner:
   `create: true` is `409 already_published`; else `updatePost` (details, author, share code, document state, `updated_at`; likes, copies,
   state and `published_at` kept; tags rewritten) and `200 { post }`.
5. `countPostsByOwner(app, owner) >= COMMUNITY_POSTS_PER_AUTHOR` (50): `409 post_limit`.
6. Another owner's post on the document: `createPost` is handed its id (`replacing`) and deletes it first in its own
   batch, under the same cap check as the insert, so a refused or failed publish keeps it (logged
   `replaced a previous owner post` once published).
7. `createPost`: one batch (the old post's delete when replacing, the row, its `post_tags`). The row is `INSERT ... SELECT ... WHERE` the owner has fewer than
   50 posts in the app, and each tag only `WHERE EXISTS` the row, so publishes racing past step 5 can't together go over:
   a refused insert is `409 post_limit`. An id collision (`posts.id` in the error) retries once with a new id; a
   `UNIQUE` failure on the document is `409 already_published`.
8. `201 { post: CommunityAppPost }` (`own: true`, `state`).

### Sync (`syncDocuments`)

`{ documents: [{ document, state }], gone: [document] }`, together at most `COMMUNITY_SYNC_MAX` (500), each id 1 to
200, each state valid, else `400 invalid_sync`. One batch: for `away`, a `DELETE … WHERE state = 'listed'` then an
`UPDATE` (the hidden ones left); one `UPDATE … WHERE document IN (json_each(?))` for each of `public` and `closed`;
one `DELETE` for `gone`; at most five statements whatever the count.

### The sweep (`sweep.ts`, the cron)

Every five minutes (`*/5 * * * *`), for each app in `COMMUNITY_APPS` with both a key (`appKey`) and an origin
(`appOrigin`, `APP_ORIGIN_<APP>`), one after another:

1. `claimSweepBatch`: `SELECT id, document, share_code, owner FROM posts WHERE app = ? AND checked_at < ? ORDER BY
checked_at LIMIT ?` with `now - COMMUNITY_SWEEP_EVERY_MS` (10 minutes) and `COMMUNITY_SWEEP_BATCH` (100), on
   `idx_posts_checked (app, checked_at)`. None due: nothing more for that app.
2. `askAppStates`: `POST <origin>/api/internal/items/community-states`, `Authorization: Bearer <COMMUNITY_KEY_<APP>>`,
   `{ posts: [{ id: document, code: share_code, owner }] }`, at most `COMMUNITY_SWEEP_TIMEOUT_MS` (10 s). Anything
   but a `200 { states: [{ id, state }] }` whose states are each `public`, `closed`, `away` or `gone`: logged
   `[community] sweep unanswered` with the app and status, and the app is left for the next run.
3. `applySweep`: the answers as one `syncDocuments` batch (`gone` into `gone`, the rest into `documents`), plus
   `UPDATE posts SET checked_at = now WHERE app = ? AND id IN (json_each(?))` for the whole batch (a document the
   app did not answer for is stamped too: it is asked again after `COMMUNITY_SWEEP_EVERY_MS`). Logged
   `[community] swept` with the app, the batch size and how many were removed, only when something changed.

A failure in one app never stops the others (each is caught and logged).

### Likes, copies, reports (`engagement.ts`)

- **Like** `setLike`: `INSERT OR IGNORE` or `DELETE` by `(post_id, liker_key)`, then `RECOUNT_LIKES`, then read the
  count, in one batch, so the answer is the count this change left.
- **Counted count**: `SUM(MIN(n, 5))` over `COUNT(*)` grouped by `network_hash` (`COMMUNITY_COUNTED_PER_NETWORK`);
  every row is stored, but one network adds at most five.
- **Copy** `recordCopy`: `INSERT OR IGNORE` by `(post_id, copier)`, then the capped recount.
- **Forget a copier** (account deleted): their copies of the app's posts deleted, those posts recounted.
- **Merge a copier** (guest signed up): copies re-keyed to `to` with `INSERT OR IGNORE` (a post both copied keeps
  one), the old rows deleted, `to`'s posts recounted.
- **Report** `recordReport`: `INSERT OR IGNORE` by `(post_id, reporter_key)`; when it inserted, `UPDATE posts SET
state = 'hidden', hidden_at = now WHERE state = 'listed'` and at least 3 distinct keys and 3 distinct network
  hashes (`COMMUNITY_AUTO_HIDE_REPORTERS`). Logged `[community] auto-hidden` when it hid.

### Reads

- **List** `listPosts(env, scope, query, owner)`: `PUBLIC_POST` for one app, `PUBLIC_POST_ANY_APP` for `all`
  (`publicWhere(scope)`), or `OWN_POST` for My Shares (one app only); `category`; every tag (`tag` param and each
  `#tag` in `q`, at most 5) as `EXISTS (post_tags …)`; every plain term (lowercased and NFC-normalised, at most 5, each cut to 40)
  as
  `search_text LIKE '%term%' ESCAPE '\'` with `\ % _` escaped; ordered `new` = `published_at DESC, id`, `loved` =
  `like_count DESC, published_at DESC, id`, `copied` likewise by `copy_count`; `LIMIT 25 OFFSET offset`. `nextOffset`
  is `offset + 24` when a 25th row came back and that does not pass `COMMUNITY_MAX_OFFSET` (2400), else null.
- **Query parsing** `parseCommunityListQuery`: `q` trimmed and cut to 200; an unknown `category` or a tag that does not
  normalise fails (`400 invalid_query`); an unknown sort is `new`; `offset` clamped to 0..2400; `sort:` and
  `category:` tokens in `q` win over the params.
- **One post**: `getPublicPost`, then `listRelatedPosts` (same category, not itself, `like_count DESC,
published_at DESC`, at most 6).
- **Featured**: likes in the last 90 days (`COMMUNITY_FEATURED_WINDOW_MS`) through `INDEXED BY idx_likes_created`,
  grouped by post and network and capped at 5 per network, joined to public posts, `recent_likes DESC, like_count
DESC, published_at DESC`, at most 6; fewer than 6 is topped up by `like_count + copy_count DESC, published_at DESC`.
- **Start With** `listStartPosts(env, app, now)`: one statement. The app's public posts on their `(app, state,
document_state)` index, each one's likes since `now - COMMUNITY_START_WINDOW_MS` on `INDEXED BY
idx_likes_post_created`, grouped by post and network and capped at 5 per network, kept with at least
  `COMMUNITY_START_MIN_LIKES`; then `CROSS JOIN posts` (so the planner cannot walk posts first) and
  `ROW_NUMBER() OVER (PARTITION BY category ORDER BY recent_likes DESC, copy_count DESC, published_at DESC, id)`,
  places 1 to `COMMUNITY_START_PER_CATEGORY`. `startResponse` groups the rows by `rowCategory` (a retired id reads as
  `other`) and slims each to a `CommunityStartPost`.
- **Facets** `facets(env, scope)`: one batch, per-category counts and the top 24 tags (`COMMUNITY_POPULAR_TAGS`,
  `n DESC, tag`), over the scope's public posts; `total` is the category sum. On `all` the counts are grouped by app
  too and also answered per app (`apps: { [app]: { [category]: n } }`), for All Apps' grouped menu.
- **A qualified category** (`categoryApp`, from `category:<app>/<id>` on All Apps) adds `p.app = ?` to the list and
  count.
- **Sitemap**: public posts `published_at DESC, id`, at most 5000 (`COMMUNITY_SITEMAP_MAX`), `{ id, updatedAt }`.
- **Hidden since**: `{ document, hiddenAt }` of the app's posts with `hidden_at >= since`, by `hidden_at`.
- **My Shares totals**: `COUNT(*)`, `SUM(like_count)`, `SUM(copy_count)` over `OWN_POST`.
- **Likes for a page**: one `SELECT post_id FROM likes WHERE liker_key = ? AND post_id IN (json_each(?))`.

## Interfaces and contracts

`GET /posts` and `GET /facets` also take `app=all` (`COMMUNITY_ALL_APPS`): every app's public posts, each naming its
`app`, and their counts (facets edge-cached under the `all` key). Any other route with `app=all` answers
`400 invalid_app`.

## Errors and edge cases

| Case                                            | Answer                                                                                                               |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `COMMUNITY_ENABLED` `false`/`0`/`off`           | every route `404 not_found` (public ones with CORS)                                                                  |
| Path outside `/api/community`                   | `404 Not found` (liveworkspace.app hosts no Community pages)                                                         |
| A post of another app, hidden, or not public    | `404` on public reads and writes                                                                                     |
| Two first publishes at once                     | the second `409 already_published`                                                                                   |
| A JSON `null` report body                       | `400 invalid_reason`, never a 500                                                                                    |
| A `tags` column that is not a JSON string array | read as no tags                                                                                                      |
| An unknown stored category                      | read as `other`                                                                                                      |
| Load More past offset 2400                      | `nextOffset: null`, so the last page never repeats                                                                   |
| An edge-cached answer (immutable headers)       | copied before CORS headers are set                                                                                   |
| A report that hid the post                      | the same `204` as one that did not                                                                                   |
| The document's owner closed their account       | its posts go at once (`/copiers/forget` with `owner`); a team's item the room's next check or the sweep sends `gone` |
| A post whose room never heard of it (migrated)  | the sweep checks it against the index like any other                                                                 |
| An app's door down or not deployed              | `[community] sweep unanswered`; nothing changes for that app                                                         |

## Security and trust

- The public never sees an owner or a document id; likes and reports carry the community key, never an owner.
- Writes from browsers are limited per network (`COMMUNITY_RATE_LIMITER`, 30 per 60 s, key `communityNetwork(ip)`),
  checked before the post is read; `clientIp` is `CF-Connecting-IP`, `127.0.0.1` locally.
- Network hashes are salted with the post id, so nothing is comparable across posts.
- App routes need the app's key; each app's key speaks only for it. `COMMUNITY_KEY_LIVEDIAGRAM`,
  `COMMUNITY_KEY_LIVEPLANNER`, `COMMUNITY_KEY_LIVEDOCUMENTS` and `COMMUNITY_KEY_LIVEDESIGN` (`appKey`, an exhaustive
  map, so a new app can't fall through to another's key).
- The app checks what only it can (ownership, publishable document) before calling.
- A post's community link is view-only for its author too: the index opens a public link at its own level whoever
  sends it (`liveworkspace/apps/index/src/access.ts` `accessTo`, `sharing.ts` `resolveShare`), so its viewer and
  embed refuse the author's edits at the grant, not only in the editor's chrome.
- The post page's embed never leaves its frame for a guest token (`createGuestTokens`, `inFrame`): a signed-out visitor
  reads it as a link visitor.

## Performance and limits

Every list is one indexed query plus one row; a sync is at most four statements; featured is two queries over the
`created_at` index; Start With is one over the app's posts and `idx_likes_post_created` (its plan pinned by a test); three answers sit at the edge (30 s, 60 s, 3600 s). Figures are in
[community.md "Performance"](../community.md#performance).

## Assets and external resources

D1, the rate-limit binding, `caches.default`. Author pictures are URLs the app sends (`https://` only); the service
never fetches them.

## Defaults ledger

- `COM1`: Load More stops at offset 2,400 (`nextOffset: null`).
- `COM2`: a report answers the same `204` whether or not it hid the post.
- `COM3`: an unknown stored category reads as `other`, and a malformed `tags` column as no tags.
- `COM4`: the sweep stamps a post the app's door did not answer for, so it waits a full interval.
