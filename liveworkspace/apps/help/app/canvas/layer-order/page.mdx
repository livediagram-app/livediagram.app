## Bringing Things to Front and Back

Right-click an element and open the **Layer** category:

- **Bring to Front** moves the element onto the tab's top [layer](/help/canvas/layers/), so nothing overlaps it. If the top layer holds anything else, a fresh layer is created above it first.
- **Send to Back** mirrors that at the bottom: the element lands on (or below) the bottom layer, so other elements paint over it.

These two buttons are how layers accumulate; a layer they empty out is removed automatically.

<AppNote app="livediagram">
  They do so even if you never open the Layers panel. Once the tab has more than one layer (and the
  Layers panel is switched on in Settings, as it is by default), the same category also shows **Move
  to layer** tiles, one per layer with a preview of what is on it, for placing the selection on a
  specific layer.
</AppNote>

Both also work from the keyboard while an element is selected (Ctrl in place of Cmd on Windows and Linux):

- **Cmd+Shift+]** brings the selection to the front.
- **Cmd+Shift+[** sends it to the back.

The menu stays open after each one, so you can adjust several elements in a row without reopening it. Layer changes are a single undoable step.

<AppNote app="livedocuments">
  Both are in the search palette too (**Cmd+K**): type **front** or **back**.
</AppNote>

<AppNote app="livediagram">
  Notes on an [event storming board](/help/canvas/event-storming-boards/) have no Layer category.
  Their menu has **Bring to Front** and **Send to Back** rows instead, which restack the note within
  its own layer and close the menu.
</AppNote>

<AppNote app="livediagram,livedesign">
  **Restacking within a layer.** The selection's floating toolbar has its own **Bring to Front** and
  **Send to Back** buttons. These are the quick nudge for two things overlapping on the same layer:
  they stack the selection in front of, or behind, everything else **on its own layer**, and never
  move it to another layer. They are on the toolbar of a single selected element; the toolbar for
  several elements has no stacking buttons, so use the right-click menu's **Layer** category for
  those.
</AppNote>

<Note>
  Newly added elements always land on top, which is what you usually want. Reach for Send to Back
  for the rarer case where a shape or a background image should sit behind your content.
</Note>

## Fading an Element with Opacity

The same Layer category holds an **Opacity** slider, from 0 to 100%. Drag it to make an element semi-transparent so whatever sits behind it stays partly visible. It's useful for a background watermark or a "ghosted" element you want present but quiet.

<AppNote app="livediagram">
  A frame that shouldn't compete with its contents is another good use.
</AppNote>

<AppNote app="livedesign,livedocuments">
  A panel that shouldn't compete with what sits on it is another good use.
</AppNote>

Opacity is a cosmetic property, so the [format painter](/help/selection-modes/format-painter/) copies it along with colours and borders, and it carries through to PNG and SVG exports.

<AppNote app="livediagram">
  A layer has an opacity of its own too, which multiplies with each element's: see [Hiding, Locking, and Dimming Layers](/help/canvas/layers-visibility-and-locking/#layer-opacity).

Exports are covered in [Exporting Diagrams](/help/account-and-data/exporting-diagrams/).

</AppNote>

<AppNote app="livedesign">
  A tab's layers can carry an opacity of their own too, which multiplies with each element's: see [Layers](/help/canvas/layers/).

Exports are covered in [Exporting Designs](/help/account-and-data/exporting-designs/).

</AppNote>

<AppNote app="livedocuments">
  Exports are covered in [Exporting Documents](/help/account-and-data/exporting-documents/).

<Tip>
  Layer order and opacity both appear in the multi-select menu too, so you can push a whole group of
  elements to the back or fade them together in one action.
</Tip>
