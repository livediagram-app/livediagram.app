A share link (the Share dialog calls each one a **pass**) is a capability: anyone holding the URL has its role. That is what makes sharing frictionless, but it also means a link left lying around keeps working. <AppName /> gives you two controls to tighten that up, a password on the <Noun /> and an expiry on each link, plus revoking a link outright. All three live in the **Share** dialog, and none of them ever stops you, the owner.

## Share Password

You can put a single password on a <Noun />: switch on **Password Protection** in the Share dialog, type it, and choose **Save**. Once it is set, anyone opening any share link for that <Noun /> must enter it before they can view, and the password rides along on every later request so their edits stay gated too.

The password is 6 to 256 characters (spaces at either end don't count). A <Noun /> shared to the Community can't have a password while its post is public.

- **One password covers every link** on the <Noun />, [embeds](/help/collaboration/sharing/embeds/) included, not one password per link. While a password is set, the live image option is unavailable, because an image can't ask for a password.
- **You always bypass it.** The owner is identified directly, so you never get prompted on your own <Noun />. So are members of the [team](/help/collaboration/teams/) whose library holds it.
- **Nobody can read it back.** <AppName /> stores only a scrambled (hashed) form of the password, so even you see just **Password Set**. Note it down when you choose it; use **Replace** or **Remove** any time.
- **Changing it takes effect at once.** Setting or replacing the password sends everyone currently in the <Noun /> through a link back to the password prompt.
- **Guessing is limited.** Share-code and password attempts are rate-limited per network (30 a minute), wherever they are tried.

<AppNote app="livedesign,livedocuments">
  A password set before hashing was introduced is converted the next time it is entered.
</AppNote>

<AppNote app="liveplanner">
  Changing the password reaches people already in the plan within a few minutes, not at once, and a
  live image of the plan shows nothing while a password is set. The guessing limit is not described
  for liveplanner.
</AppNote>

## Link Expiry

When you create a pass, the **Valid** control sets its lifetime, so access ends automatically without you having to remember to revoke it.

| Choice   | Lifetime                |
| -------- | ----------------------- |
| Forever  | no expiry (the default) |
| 1 week   | 7 days                  |
| 1 month  | 30 days                 |
| 6 months | 183 days                |

When a link expires it stops granting access everywhere at once: the share URL, its embed and live image, and the real-time room all behave as if the link were revoked. The expired link does not vanish, though. It moves to the **Expired** section of the Share dialog, where you can delete it or **Extend** it for the same lifetime again, counted from now. A link's lifetime can't be changed after it is created. See [Share Link Expiry](/help/collaboration/sharing/share-link-expiry/).

<AppNote app="livehuddle">
  **Link previews.** Paste a share link into Slack, Microsoft Teams, Discord, iMessage, WhatsApp, X or LinkedIn and its preview shows the Space's name and a picture of its tab: the link's own tab for a [link to one tab](/help/collaboration/sharing/one-tab/), otherwise the first. The picture is the same one a [live image](/help/collaboration/sharing/live-image/) shows, and it updates after the Space is saved.

A preview never gives away more than the link does. These show only the plain livehuddle card, with no name and no picture:

- A link to a Space with a **share password**.
- A link that is revoked or expired, or to a Space in the Trash.
- A Space's own address, which only its owner can open, so pasting it in a public channel tells the channel nothing.

So if a Space's name or first tab is sensitive, set a share password before you paste its link anywhere public.

</AppNote>

<Note>
  Existing live sessions are not force-disconnected at the exact expiry moment; a visitor loses
  access on their next load or save. To cut someone off instantly, revoke the link instead: revoking
  disconnects everyone using it straight away.
</Note>

<AppNote app="liveplanner">
  Access is checked with short-lived passes that are renewed every few minutes, so a change to the
  password or a team reaches people already in the plan within a few minutes. Revoking a link, or
  changing which tabs it opens, is faster: everyone using it is sent out or reloaded straight away.
</AppNote>

<Tip>
  Use the two together for sensitive work: a password stops casual access, and an expiry bounds how
  long even the right people keep it. Remember that anyone who can see an embed's page source can
  see its link.
</Tip>
