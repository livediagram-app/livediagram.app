The liveknowledge tools, served by liveworkspace's one MCP at `https://mcp.liveworkspace.app/mcp`, speak in pages. Every answer about a page or a passage says how far it can be trusted, so an agent can tell a verified answer from a stale one. To connect a client, see [Connecting an Agent](/help/knowledgebase/connecting-an-agent/).

## The Page Tools

| Tool           | What it does                                                                                                        | Scope     |
| -------------- | ------------------------------------------------------------------------------------------------------------------- | --------- |
| `get_knowledge_context`  | The Always in Context pages, whole, as Markdown, in tree order and within 8,000 tokens; the caller's role and scopes; the Review Period. Call it first | `read`    |
| `list_knowledge_pages`   | The page tree: each page's id, title, depth, parent, subpage count, owner and trust, and the Review Period once     | `read`    |
| `search_knowledge_pages` | Passages that match a query: titles first, then passages, verified pages before others, each with its page and headings | `read`    |
| `read_knowledge_page`    | One page as Markdown, with the pages that link to it and its subpages                                               | `read`    |
| `report_knowledge_gap`   | Records a question the Knowledgebase does not answer, for Questions Nobody Could Answer. Changes no page            | `read`    |
| `create_knowledge_page`  | A new page from Markdown, under a parent or at the top level. Never Verified                                        | `suggest` |
| `suggest_knowledge_edit` | A change to a page, with a reason: replace a passage (`old_text` with `new_text`) or append. Waits for a person      | `suggest` |
| `write_knowledge_page`   | Replaces a page's writing with Markdown, or appends to it, at once. Never on a Verified or Review Due page          | `write`   |
| `move_knowledge_page`    | Moves a page and its subpages to another parent or the top level, before a named sibling or last                    | `suggest` for a never-verified subtree, else `write` |

A page is named by its id, or by its title where one page alone has that title. `[[Title]]` in Markdown is a link to the page of that title.

## The Trust Fields

Every page and passage in an answer carries:

| Field            | Means                                                                    |
| ---------------- | ------------------------------------------------------------------------ |
| `verified`       | `verified`, `review-due` or `never-verified`                             |
| `verified_at`    | When it was last verified                                                |
| `verified_by`    | Who verified it (on `read_knowledge_page`)                                         |
| `review_due`     | When its review comes due, from the Knowledgebase's Review Period        |
| `stale`          | `true` when the review is due                                            |
| `conflicts_with` | The pages it disagrees with, while a disagreement is open, each with the `question` the two answer differently and when it was found (`found_at`); only where the connection can read both pages |

`get_knowledge_context` and `list_knowledge_pages` also give the Review Period once, as `review_period`: `30 days`, `90 days`, `180 days`, `365 days` or `never`. No tool sets it.

## Small Answers

Answers are small unless the agent asks for more, and each names the tool to call next.

| Tool           | By default                      | At most                 |
| -------------- | ------------------------------- | ----------------------- |
| `search_knowledge_pages` | 8 passages                      | 20                      |
| `list_knowledge_pages`   | 100 pages                       | 500                     |
| `read_knowledge_page`    | The first 6,000 characters      | Pass `heading` for one section, or a larger `max_chars` |

A search is at most 200 characters, a gap's question 1,000, a suggestion 20,000 characters with a reason of 500.

## The Scopes

`read` covers the five read tools; `suggest` adds `create_knowledge_page`, `suggest_knowledge_edit`, and `move_knowledge_page` for a page whose subtree has never been verified; `write` adds `write_knowledge_page`, and `move_knowledge_page` for any page. A connection your AI tool makes holds `read` and `suggest`. Only an Editor grants `write`, for one connection in one Knowledgebase. A person's role still bounds the agent: a Viewer's agent only reads. See [What Agents Can Do](/help/knowledgebase/what-agents-can-do/).

## The Knowledgebase Tools

liveknowledge has 29 tools in all, and the same ten core tools as every app. An AI tool finds them with `list_app_tools` (kind `knowledgebase`) and runs one with `read_with_app_tool` or `change_with_app_tool`, or by name when its client asks for every tool at once (the address with `?tools=all`). Besides the page tools, there are the tools every liveworkspace app has, in a Knowledgebase's words: `find_knowledgebases`, `create_knowledgebase`, `rename_knowledgebase`, `share_knowledgebase`, `archive_knowledgebase`, `unarchive_knowledgebase`, `delete_knowledgebase`, `restore_knowledgebase`, `list_knowledge_trash` and `list_knowledge_templates`, the comment tools `list_knowledge_threads` and `change_knowledge_threads`, and the picture tools `list_knowledge_images`, `upload_knowledge_image` and `delete_knowledge_image`. Sharing, archiving and deleting a whole Knowledgebase need a full token, whatever the scopes. The same ten core tools (`find_items`, `read_item`, `create_item` and the rest) reach a Knowledgebase too, by its ref, `knowledgebase:` followed by its id.

## Good to Know

- Every read an agent makes is counted for [Connected Agents](/help/knowledgebase/connecting-an-agent/), under the name its client gives.
- A search that finds nothing is recorded as a question nobody could answer.
- The tool descriptions tell an agent what to do: call `get_knowledge_context` first, prefer a verified passage, say so when it relies on a stale one, and report a gap rather than guess.
