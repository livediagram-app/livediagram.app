External API calls authenticate with an **API token**: a long-lived, revocable credential that acts as your account.

## Get a token

<AppNote app="livediagram,livedocuments,livedesign,livehuddle">

Tokens are made in **Settings**, **Developers**, **API Tokens**, in <AppName /> or any liveworkspace app (or on [liveworkspace.app](https://www.liveworkspace.app/explorer?settings=tokens)), not through the API. The secret is shown **once** at creation; copy it then, because it is never displayed again. See [API Tokens](/help/account-and-data/api-tokens/) for the full walkthrough, including the six-month lifetime and the 20-token limit.

</AppNote>

<AppNote app="liveplanner">

Tokens are made in Settings, not through the API. In liveplanner, open **Settings**, choose **Developers**, then **API Tokens** beneath it, and make the token there; the same list is in every liveworkspace app's Settings and on [liveworkspace.app](https://www.liveworkspace.app/explorer?settings=tokens). The secret is shown **once** at creation; copy it then, because it is never displayed again. See [API Tokens](/help/account-and-data/api-tokens/) for the full walkthrough, including the read-only option, the six-month lifetime and the 20-token limit.

</AppNote>

Tokens have the form `lwt_` followed by a random string, so they are easy to spot in logs and secret scanners.

</AppNote>

## Send the token

Pass the token in the `Authorization` header as a bearer credential on **every** request. There is no separate login or session step.

<AppNote app="livediagram">

```bash
curl https://www.livediagram.app/api/documents \
  -H "Authorization: Bearer lwt_your_token_here"
```

</AppNote>

<AppNote app="liveplanner">

```bash
curl https://www.liveplanner.app/api/projects \
  -H "Authorization: Bearer lwt_your_token_here"
```

</AppNote>

<AppNote app="livedocuments">

```bash
curl https://www.livedocuments.app/api/documents \
  -H "Authorization: Bearer lwt_your_token_here"
```

</AppNote>

<AppNote app="livedesign">

```bash
curl https://www.livedesign.app/api/designs \
  -H "Authorization: Bearer lwt_your_token_here"
```

</AppNote>

<AppNote app="livehuddle">

```bash
curl https://www.livehuddle.app/api/documents \
  -H "Authorization: Bearer lwt_your_token_here"
```

</AppNote>

<AppNote app="livediagram,livedesign">

Every request authenticated this way acts as your account, with the same access to your <Noun plural />, folders and content that you have in the editor. Account administration (managing teams, creating or listing tokens, deleting the account) needs a signed-in session and is refused to a token. A read-only token (one you created when [connecting an AI tool](/help/account-and-data/connect-ai-mcp/) with **Read-only access** on) can read (except a <Noun />'s share-link list, which would hand it edit links), and every write is refused except revoking itself and opening or pairing a (view-only) workbench.

</AppNote>

## Check or retire the token you are using

`GET /tokens/current` describes the token the request presented: its account, name, whether it is read-only, and when it expires. It is a cheap way for a script to confirm its credential works. `DELETE /tokens/current` revokes that same token, so a script can clean up after itself without you opening Settings.

<AppNote app="livediagram">

```bash
curl https://www.livediagram.app/api/tokens/current \
  -H "Authorization: Bearer lwt_your_token_here"
```

</AppNote>

<AppNote app="liveplanner">

```bash
curl https://www.liveplanner.app/api/tokens/current \
```

</AppNote>

## You need an account

<AppNote app="livediagram,livedocuments,livedesign,livehuddle">

API tokens are a **signed-in-only** feature. The <Noun />, sharing, and real-time collaboration all stay account-free for guests, but programmatic API access requires [signing in](/help/account-and-data/signing-in/), the same as [teams](/help/collaboration/teams/).

</AppNote>

<AppNote app="liveplanner">

API tokens are a **signed-in-only** feature. The editor, sharing, and real-time collaboration all stay account-free for guests, but programmatic API access requires [signing in](/help/account-and-data/signing-in/), the same as [teams](/help/collaboration/teams/).

</AppNote>

## Tokens versus the guest path

<AppNote app="livediagram,livehuddle">

The editor itself does not use an API token. When you are not signed in, the app identifies you with your [guest identity](/help/account-and-data/guest-identity/), a guest token kept in your browser and sent as a bearer token. That path is for the first-party app only: it is not a credential you should build integrations on. For anything outside the editor, use an API token.

</AppNote>

<AppNote app="liveplanner,livedocuments">

The editor itself does not use an API token. When you are signed in it sends your account's short-lived access token, and when you are not, a [guest](/help/account-and-data/guest-identity/) token that liveworkspace issued to this browser. Those are for the first-party app only: they are not credentials you should build integrations on. For anything outside the editor, use an API token.

</AppNote>

<AppNote app="livedesign">

The editor itself does not use a token. When you are not signed in, the app identifies you with a [guest token](/help/account-and-data/guest-identity/) that liveworkspace.app gives your browser, sent as a bearer token just as a signed-in session's is. That path is for the first-party app only: it is not a credential you should build integrations on, and it is not used like a token. For anything outside the editor, use a bearer token.

</AppNote>

## Keep tokens safe

<Note>
  A token has your account's full read and write access to your <Noun plural />. Treat it like a
  password: keep it out of source control and shared logs, and never put it in client-side code that
  ships to a browser. If a token might have leaked, revoke it in **Settings**, **Developers**, **API
  Tokens** and create a replacement.
</Note>

## Errors

<AppNote app="livediagram,liveplanner,livedocuments">

A request with no credential, or a bearer that is not an API token, is refused with `400 bad_request` (its message begins `authentication required`); an `lwt_` token that is unknown, expired, or revoked is refused with `401 invalid_token`. See [Errors and Rate Limits](/help/developers/errors-and-rate-limits/) for the status codes and the error response shape.

</AppNote>

<AppNote app="livedesign">

A request with no credential, or one whose bearer does not verify, is refused with `400 bad_request` (its message begins `authentication required`); an `lwt_` token that is unknown, expired, or revoked is refused with `401 invalid_token`. See [Errors and Rate Limits](/help/developers/errors-and-rate-limits/) for the status codes and the error response shape.

</AppNote>

<AppNote app="livehuddle">

A request with no credential, or a bearer livehuddle does not recognise, is refused with `400 bad_request` (its message begins `authentication required`); an `lwt_` token that is unknown, expired, or revoked is refused with `401 invalid_token`. See [Errors and Rate Limits](/help/developers/errors-and-rate-limits/) for the status codes and the error response shape.

</AppNote>
