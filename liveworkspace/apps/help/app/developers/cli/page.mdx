<AppNote app="livediagram">

`livediagram` is a command line for the livediagram API. It is built first for **coding agents** (an agent working in your repository, or one changing a diagram while you talk to it) and second for **scripts**: finding canvases, reading a tab as text, changing it with edit operations, answering comments, and syncing canvases to files.

</AppNote>

<AppNote app="liveplanner">

`liveplanner` is a command line for the liveplanner API. It is built first for **coding agents** (an agent working in your repository, or one updating your board while you talk to it) and second for **scripts**: finding plans, reading a tab as text, adding and moving cards, filling in Sheets, answering comments, and syncing plans to files.

</AppNote>

<AppNote app="livedocuments">

`livedocuments` is a command line for the livedocuments API. It is built first for **coding agents** (an agent working in your repository, or one changing a document while you talk to it) and second for **scripts**: finding documents, reading a tab as text, changing it with edit operations, answering comments, and syncing documents to files.

</AppNote>

<AppNote app="livedesign">

`livedesign` is a command line for the livedesign API. It is built first for **coding agents** (an agent working in your repository, or one changing a design while you talk to it) and second for **scripts**: finding designs, reading a tab as text, changing it with edit operations, answering comments, and syncing designs to files.

</AppNote>

It sits beside the [MCP server](/help/account-and-data/connect-ai-mcp/), not in place of it. Both call the same [API](/help/developers/api-overview/) with an [API token](/help/account-and-data/api-tokens/), and the API owns every change, so an older copy of the CLI never writes the old way.

## Install

<AppNote app="livediagram">

The CLI is the npm package `@livediagram/cli` and needs **Node 22 or later**. Run it without installing:

```bash
npx @livediagram/cli --help
```

or install it, which gives you the `livediagram` command:

```bash
npm install -g @livediagram/cli
livediagram --version
```

The examples below use the installed `livediagram`; with `npx`, put `npx @livediagram/cli` in its place.

## Where Your Token Is Kept

<AppNote app="livediagram">

A stored token goes in your operating system's own secret store: the macOS Keychain, the Secret Service on Linux (through `secret-tool`), or on Windows the token sealed to your user account by Windows' own data protection. Where that store is unavailable, the token is kept in `~/.config/livediagram/credentials.json`, readable only by you, and the CLI tells you so when it stores it there. If it finds that file readable by others, it tightens it and warns you.

**Cards, Boards and Sheets**

```bash
liveplanner item ls "Sprint 14"                      # the cards, by number such as #12
liveplanner item ls "Sprint 14" --status "To Do" --status Doing --type bug   # only these columns and card types
liveplanner item ls "Sprint 14" --query checkout --updated-since 2026-11-01  # open cards holding "checkout", changed since
liveplanner item add "Sprint 14" "Fix login" --type task --status "To Do" --fields priority=high
liveplanner item move "Sprint 14" "#12" "In Progress"
liveplanner item set "Sprint 14" "#12" --fields assignee=Sam --clear due
liveplanner item ls "Sprint 14" --handed-to-me          # the open cards handed to this token's AI assistant
liveplanner item hand-back "Sprint 14" "#12"              # give one back to its person when done
liveplanner board add "Sprint 14" --preset sprint
liveplanner board set "Sprint 14" Kanban --columns "To Do,Doing,Review,Done"
liveplanner board set "Sprint 14" Kanban --add-widgets "Budget Sum,due"    # show widgets in the board's header
liveplanner board set "Sprint 14" Kanban --remove-widgets people           # hide one again
liveplanner type ls "Sprint 14"                      # card types and their fields
liveplanner type apply "Sprint 14" -f types.json     # add, change or delete card types
liveplanner sheet add "Budget 2027" --title Costs --csv costs.csv
liveplanner sheet get "Budget 2027" Costs A1:D20     # a sheet's cells by A1, formulas worked out
liveplanner sheet set "Budget 2027" Costs B2 1200 =B2*12
```

Cards, boards and sheets are named the way the editor shows them: a column by its name, a card by its number, a sheet by its title. These writes are not changesets: each lands at once, for everyone with the plan open.

To empty a field, name it in `--clear` (`--clear due`). A field that holds several values, such as Blocked By, also clears with `key=` and nothing after it (`--fields "Blocked By="`). To flag a card for attention, set `--fields flagged=true` on `item add` or `item set`; `--clear flagged` (or `flagged=false`) takes the flag off, and `item ls` ends a flagged card's line with `flagged`. `board set --add-widgets` and `--remove-widgets` take widget names or ids, separated by commas.

A card [handed to an AI assistant](/help/plan/cards/#hand-a-card-to-an-ai-assistant) is handed to a token: `--handed-to-me` lists the open ones handed to the token you run with, `--fields assignee=me` hands one to it, and `item hand-back` gives one back to the token's person. A session (no token) has no assistant, so each of these is refused.

`item ls` lists every card unless you narrow it. `--type` and `--status` take a card type or a column, and repeat for several. `--query` keeps the cards whose title or description holds the text, and `--updated-since` the ones changed since a date or time (`2026-11-01`, `2026-11-01T09:00:00Z`). With either of those two, closed cards (in a done column such as Done, trashed or archived) are left out, as they are for an AI assistant, and the last line says how many: add `--include-closed` to list them too, or name their column with `--status`.

## Output and Exit Codes

<AppNote app="livediagram">

The CLI never prompts when its input or output is not a terminal, so it is safe in pipes, scripts and CI. (In a terminal, only `link init` without `--folder` or `--doc` asks you to pick a folder.) **stdout carries only data**; hints, warnings and errors go to stderr. Output is compact text; `--json` gives the same data as JSON, `--json=id,name` picks fields, and `-q` prints only refs or ids. A list that was cut short ends with a line saying how to see the rest.

</AppNote>

## Errors and Rate Limits

The CLI is subject to the same limits as any API client, per token: on the hosted service, **300 writes** and **120 reads a minute**. Over that, a command exits with `6` and asks you to wait a minute and retry. A read-only token's writes exit with `4`. [Errors and Rate Limits](/help/developers/errors-and-rate-limits/) has the full list and the status codes behind these exit codes.

The first time it counts one, it says so. Turn it off with `liveplanner telemetry off`, `LIVEPLANNER_TELEMETRY=0` or `DO_NOT_TRACK=1`.

## Updates

<AppNote app="livediagram">

Once a day at most, the CLI asks npm in the background whether a newer version is out. When one is, the next command that succeeds says so in one line, for example `livediagram 1.4.0 is out (you have 1.2.1). Update: npm i -g @livediagram/cli`, at most once a day. It never asks in CI or when its messages are not going to a terminal, and it never slows a command down. Turn it off with `LIVEDIAGRAM_NO_UPDATE_CHECK=1`.

</AppNote>

## Keep It Safe

<AppNote app="livediagram">

<Note>
  A full-access token can change and share everything you can. Give an agent a **Read-only access**
  token when it only needs to read, keep `LIVEDIAGRAM_TOKEN` out of source control and logs, and
  revoke a token in **Settings**, **Developers**, **API Tokens** (or with `livediagram auth logout`)
  the moment you no longer need it or think it may have leaked.
</Note>
