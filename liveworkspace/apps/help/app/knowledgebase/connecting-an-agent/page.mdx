A Knowledgebase is written for agents as much as for people. Connect Claude, a coding agent or your own script, and it can search the pages, read them with how far each can be trusted, and suggest edits for a person to accept.

There are three ways in: the MCP server, the command line and an API token. The **Connect** tab walks you through each, with the address and the commands to copy.

<Figure caption="Connect: pick your AI app, follow its steps with the address to copy, and watch for it to connect.">
  <ConnectAgentScene />
</Figure>

## Open Connect

<Step n={1}>
  Sign in, then press the **Connect** tab in the footer, after Insights. **Connect an Agent** in Insights opens it too.
</Step>

<Step n={2}>
  Follow its four steps: **Pick Your AI App**, **Add liveknowledge** to it, **Approve and Choose Access**, and **Check It Worked**.
</Step>

Every role can follow the steps. What a connection can then do depends on who it acts for (see [What Agents Can Do](/help/knowledgebase/what-agents-can-do/)). Signed out, Connect asks you to sign in first: connecting makes a token for your account.

## Through the MCP Server

This is the way for Claude and any other AI tool that speaks the Model Context Protocol.

<Step n={1}>
  In **Connect**, pick your AI app: Claude, Claude Code, ChatGPT, Cursor, VS Code or Other App.
</Step>

<Step n={2}>
  Follow its steps. Each gives you the address, `https://mcp.liveknowledge.app/mcp`, or the command or config that holds it, with **Copy**. In Claude, for example, open Settings, then Connectors, and add a custom connector with the address as its URL. For every app, see [Connecting AI Tools](/help/account-and-data/connect-ai-mcp/ai-clients/).
</Step>

<Step n={3}>
  Your AI tool opens a liveknowledge page asking you to approve the connection. Check the site it names, switch on **Read-only access** if it should only read, and choose **Connect**. The tool makes its own token, so there is nothing to paste.
</Step>

<Step n={4}>
  Ask it something about your pages, naming the Knowledgebase: Connect gives you a first prompt to copy. **Check It Worked** says **Connected** with the app's name once it reads a page here; it checks every 10 seconds for 5 minutes, and **Check Again** starts again. The app calls `get_context` first, then `search_pages`, `read_page` and `suggest_edit`. Every tool is listed in [The liveknowledge MCP Tools](/help/developers/liveknowledge-mcp-tools/).
</Step>

## Through the Command Line

The `liveknowledge` command reads and suggests from a terminal or a script.

```bash
liveknowledge auth login
liveknowledge context Handbook
liveknowledge search Handbook when do we deploy
```

`auth login` signs you in once in the browser. Every other command takes the Knowledgebase's name (or its id, or its address). See [The liveknowledge CLI](/help/developers/liveknowledge-cli/).

## With an API Token

<Step n={1}>
  Press **Open API Tokens** under **Other Ways In** in Connect. It opens the Tokens page in Settings.
</Step>

<Step n={2}>
  Create a token and copy it. It is shown once.
</Step>

<Step n={3}>
  Send it to the API as `Authorization: Bearer <token>`. See [API Tokens](/help/account-and-data/api-tokens/) and [The Knowledge API](/help/developers/knowledge-api/).
</Step>

A read-only token only reads, whatever is allowed in the Knowledgebase.

## See It Connected

Once an agent has read or written this Knowledgebase, it has a card under **Connected Agents** in Insights.

<Figure caption="A connected agent's card: its name, how it connects, what it may do, and the pages it read most. An Editor's menu on it holds Allow Writing.">
  <AgentCardScene />
</Figure>

- **The name** is the one the AI tool gives itself, or "CLI" for the command line.
- **How it connects:** "Through the MCP server", "Through the command line" or "With an API token", and when it was last seen.
- **What it may do,** as chips: **Reads**, **Suggests Edits** and, once an Editor allows it, **Writes**.
- **Pages read this week,** and the three it read most. Press one to open it.

A card stays for 30 days after the agent last read or wrote here.

## Good to Know

- An agent acts for the person or token that connected it, and can open only what they can. A share role applies to an agent exactly as it does to a person.
- A new connection reads and suggests. Writing is allowed one connection at a time, by an Editor. See [What Agents Can Do](/help/knowledgebase/what-agents-can-do/).
- A Knowledgebase kept Offline is in your browser only, so no agent can reach it, and its Connect tab waits for it to be synced.
- A connection reaches every Knowledgebase you can open. Name this one when you ask, so the app reads here.

## Who Can Do What

| Action                                   | Editor | Participant | Viewer |
| ---------------------------------------- | ------ | ----------- | ------ |
| Open Connect, see Connected Agents       | Yes    | Yes         | Yes    |
| Connect an agent that reads              | Yes    | Yes         | Yes    |
| Connect an agent that suggests edits     | Yes    | Yes         | No     |
| Allow an agent to write, or stop it      | Yes    | No          | No     |
