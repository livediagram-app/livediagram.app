An agent connected to a Knowledgebase can do three kinds of thing, each called a **scope**: read, suggest and write. A new connection holds the first two. Writing is something an Editor allows, for one connection, in one Knowledgebase.

## The Three Scopes

| Scope     | Chip on its card   | What it lets the agent do                                                                 |
| --------- | ------------------ | ----------------------------------------------------------------------------------------- |
| `read`    | **Reads**          | Read the context pages, the page tree and pages; search; report a question nobody could answer |
| `suggest` | **Suggests Edits** | Everything `read` does, plus create a page, suggest an edit to a page, and move a page nobody has verified |
| `write`   | **Writes**         | Everything `suggest` does, plus replace a page's writing (as far as AI Editing allows) and move any page |

- A full API token, and a connection your AI tool made through the MCP server, hold `read` and `suggest`.
- A read-only token holds `read` only, and can never hold more.
- `write` is never given by a token. An Editor grants it in the Knowledgebase, and it applies there alone.

## Moving Pages

An agent that builds pages can also put them in order. With `suggest`, it moves a page to another parent or another place in the tree when the page, and every page under it, has never been verified: the drafts it made. Moving changes none of a page's writing, and links to it keep working.

- A page that is **Verified** or **Review Due**, or one with such a page under it, still needs `write`. The agent is told which page holds it back, and can ask you to move it.
- AI Editing does not limit moving: it bounds what an agent writes, and a move writes nothing.
- Anyone watching the page hears of a move to a new parent under the agent's name, as they would of yours.

## The Person Behind the Agent Still Counts

An agent acts for the person or token that connected it, and never does more than that person could:

- A **Viewer's** agent only reads, whatever its scopes.
- A **Participant's** agent can suggest edits and move pages nobody has verified, but not create pages or write.
- An **Editor's** agent can create pages and suggest edits, and can be allowed to write.

## Allow an Agent to Write

<Step n={1}>
  Open the **Insights** tab in the footer, press the **Agents** tile, and find the agent under **Connected Agents**.
</Step>

<Step n={2}>
  Press the More button (⋯) at the right of its card and choose **Allow Writing**.
</Step>

<Step n={3}>
  The dialog says what writing allows. Confirm with **Allow Writing**. The card shows a **Writes** chip at once.
</Step>

To take it back, choose **Stop Writing** from the same menu and confirm. The agent goes back to reading and suggesting. Nothing it has written is undone.

A card with no menu cannot be allowed to write, and says why: its token is read-only, or the person it acts for is not an Editor here.

## AI Editing

**AI Editing** is a setting of the whole Knowledgebase that says how far any agent may change pages itself. An agent may do the lower of the two: what its connection holds, and what AI Editing allows.

| Level                                   | What an agent that may write does                                                       |
| --------------------------------------- | --------------------------------------------------------------------------------------- |
| **Suggest Edits Only** (the default)    | Nothing directly. Every change is a suggestion for a person to accept.                   |
| **Edit Unverified Pages**               | Rewrites pages nobody has verified. A **Verified** or **Review Due** page takes a suggestion. |
| **Edit Any Page**                       | Rewrites any page, verified ones too. Every change is marked **AI Edited**.               |

Under **Edit Any Page** one more switch shows: **Remove Verification When AI Edits**. Off (the default), a verified page an agent rewrites stays Verified, as it does when a person edits it. On, it goes back to **Not Verified**, so a person checks it and verifies it again. The owner stays.

<Step n={1}>
  Press the Knowledgebase's name at the top of the sidebar to open its menu, and choose **AI Editing**.
</Step>

<Step n={2}>
  Choose a level, and under **Edit Any Page** whether to remove verification. Press **Save**.
</Step>

Only an Editor sees **AI Editing**, and no agent, token or command can change it. A connection without **Allow Writing** only suggests, whatever the level. Agents read the level from `get_knowledge_context` (the CLI's `context`), so they know whether to write or suggest. A refused write names the setting and tells the agent to use `suggest_knowledge_edit`.

## What an Agent Never Does

- It never verifies a page. A page an agent creates is **Never Verified**.
- No MCP tool or CLI command changes the Review Period, AI Editing or Knowledgebase Style. An Editor sets them in the app.
- It never sees the team's AI key, if it added one.
- It never reaches a Knowledgebase kept Offline.

## Good to Know

- Allowing writing applies to one connection in one Knowledgebase. The same agent connected to another Knowledgebase still only reads and suggests there.
- Each confirmation reads "This applies to this knowledgebase only."

## Who Can Do What

| Action                                | Editor | Participant | Viewer |
| ------------------------------------- | ------ | ----------- | ------ |
| See what each agent may do            | Yes    | Yes         | Yes    |
| Allow an agent to write, or stop it   | Yes    | No          | No     |
| Change AI Editing                     | Yes    | No          | No     |
