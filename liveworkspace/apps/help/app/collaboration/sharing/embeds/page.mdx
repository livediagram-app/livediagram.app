## What an Embed Shows

The embed is built from a share link, and it **honours that link's role**: it embeds a read-only <Noun /> or an editable one, so readers of the host page can change the <Noun /> right there only if the link is an Editor's. Pick the pass to match: a read-only pass when the page is for an audience, an Editor pass when it is for collaborators.

<AppNote app="livediagram">
  A **Viewer** or **Participant** pass embeds a read-only canvas, while an **Editor** pass embeds an
  editable one.
</AppNote>

<AppNote app="livedesign">
  A **Viewer** or **Participant** pass embeds a read-only design, while an **Editor** pass embeds an
  editable one.
</AppNote>

<AppNote app="livedocuments">
  A **Viewer** or **Participant** pass embeds a read-only document, while an **Editor** pass embeds
  an editable one.
</AppNote>

<AppNote app="livehuddle">
  A **Participant** pass (or a legacy **Viewer** pass made before livehuddle stopped offering them)
  embeds a read-only space, while an **Editor** pass embeds an editable one. Pick a Participant pass
  when the page is for an audience.
</AppNote>

<AppNote app="liveplanner">
  A **Viewer** or **Participant** link embeds a read-only plan, while an **Editor** link embeds an
  editable one, so readers of the host page can move cards and edit cells right there.
</AppNote>

Inside the frame, the embed:

- hides the header and the tab bar, leaving a clean view,
- keeps a small **Open in <AppName />** badge that opens the full share view in a new tab,
- stays in the same realtime room as any viewer, so it **live-updates**: when the <Noun /> changes, the embedded view follows along.

</AppNote>

## Adding an Embed to a Page

<Step n={1}>Open the **Share** dialog and create or pick a pass for the <Noun />.</Step>
<Step n={2}>Open the pass's **Embed** menu, under its link, and choose **Copy iframe** for a ready-made `<iframe>` snippet, or **Copy embed URL** for the bare URL.</Step>
<Step n={3}>Paste it into your page, wiki, or doc: the iframe snippet drops in directly, while the embed URL suits tools that turn a pasted link into an embed themselves.</Step>

<AppNote app="liveplanner">
  The embed address looks like `https://www.liveplanner.app/embed?s=CODE`. To create a pass for the

## Pasting a Share Link

You don't have to copy a snippet at all. Paste the share link itself into a tool that reads oEmbed, such as Notion, Medium or Ghost, and it unfolds into a live, read-only view of the <Noun />. Slack may show only the link's preview card (the name and a picture) until it lists <AppName /> as an oEmbed provider, so don't count on a live view there.

- **Always read-only.** Even a link from an Editor pass unfolds as a viewer, so a public page never hands its readers edit rights. To embed something people can edit, use the iframe snippet from an Editor pass, as above.
- **Only what the link shows.** A link that is revoked, [expired](/help/collaboration/sharing/share-link-expiry/) or in the trash, or that has a [share password](/help/collaboration/sharing/share-passwords/), doesn't unfold: the tool keeps the plain link. A host may keep an unfolded copy for up to five minutes after you revoke a link, but the frame itself shows the not-found message as soon as it loads.

## When an Embed Stops Working

An embed lives exactly as long as its share link. If you revoke the link, or it [expires](/help/collaboration/sharing/share-link-expiry/), the frame shows a small not-found message instead of the <Noun />. Create a new pass and paste its snippet to bring it back.

## Privacy

An embed only exposes what the share link exposes: a read-only link's embed is a read-only view, and only an Editor link's embed can change the <Noun />. Anyone who can read the host page's source can also see the embed URL, so treat an editable embed like handing out the edit link itself.

<AppNote app="livediagram,livedesign">An embed has no way to put a name on what someone adds.</AppNote>

  pass's embed is read-only.
</AppNote>
