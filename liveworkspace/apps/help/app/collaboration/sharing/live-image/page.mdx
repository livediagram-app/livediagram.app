A live image is a plain image address for a <Noun /> that **follows the <Noun /> as it changes**: the server keeps a picture of it that is redrawn after each save, so wherever you place the address shows the current state of the <Noun />. It is the companion to an [embed](/help/collaboration/sharing/embeds/): the embed is interactive, while a live image is a single static picture, which is exactly what you need somewhere an `<iframe>` is not allowed, like a **GitHub README** or a Markdown file.

## How It Differs from an Embed

Both come from a share link and both stay current, but they suit different homes:

- An **embed** is an interactive frame, updating in real time. Best for wikis, Notion, and your own pages.
- A **live image** is a static picture served at an address. It does not pan or zoom, but it drops into anywhere that accepts an image, including places that strip iframes. It catches up to your edits on the next load.

## Getting a Live Image

<Step n={1}>Open the **Share** dialog and create or pick a pass for the <Noun />.</Step>
<Step n={2}>Open the pass's **Live image** menu, beside **Embed**, and choose the format you need: **Copy image URL** for the bare link, **Copy Markdown** for a Markdown image snippet, or **Copy HTML** for an `<img>` tag.</Step>
<Step n={3}>Paste it where you want the picture to appear. A README takes the Markdown; a web page takes the HTML or the raw URL.</Step>

## Scoping the Image to One Tab

By default the image shows the <Noun />'s first tab. When the <Noun /> has more than one tab, the **Live image** menu also shows a **Tab** dropdown: pick a tab and every copy option (image URL, Markdown, HTML) carries a tab parameter that scopes the image to that tab. A pass scoped to [one tab](/help/collaboration/sharing/one-tab/) always shows its own tab, so its menu has no **Tab** dropdown.

## When It Is Not Offered

A live image only works for a link that opens without a password. An `<img>` request cannot supply one, so while the <Noun /> has a [share password](/help/collaboration/sharing/share-passwords/), its image address shows nothing and the pass offers no **Live image** menu. Remove the password to use a live image, or use an [embed](/help/collaboration/sharing/embeds/), which can ask for the password inside its frame.

<AppNote app="livediagram">
  The menu is hidden on every pass while the canvas has a password, and the server refuses an image for a protected canvas rather than leak it. That includes image URLs you copied before setting the password: they stop showing the canvas.
</AppNote>

<AppNote app="livedesign">
  The menu is hidden on every pass while the design has a password, and the server refuses an image for a protected design rather than leak it. That includes image URLs you copied before setting the password: they stop showing the design.
</AppNote>

<AppNote app="livedocuments">
  The menu is hidden on every pass while the document has a password, and the server refuses an image for a protected document rather than leak it. That includes image URLs you copied before setting the password: they stop showing the document.
</AppNote>

<AppNote app="livehuddle">
  The menu is hidden on every pass while the space has a password, and the server refuses an image for a protected space rather than leak it. That includes image URLs you copied before setting the password: they stop showing the space.
</AppNote>

A live image also stops working when its share link is revoked or [expires](/help/collaboration/sharing/share-link-expiry/), so keep the link alive for as long as the image is in use.

## Privacy

A live image only exposes what its share link exposes, as a flat picture with no editing actions.
