Every AI tool connects to <AppName /> the same way: you give it one address, the same for every liveworkspace app, and the first time it uses it, you approve the connection on a liveworkspace page. Connect once and the tool reaches every app you tick there, so you never add a server per app. This article walks through that for the tools people use most. For what the AI can do once it is connected, see [Connect an AI Tool (MCP)](/help/account-and-data/connect-ai-mcp/).

You need a <AppName /> account: connecting an AI tool is a signed-in-only feature.

## The Address

There is one address for every liveworkspace app, <AppName /> included:

```text
https://mcp.liveworkspace.app/mcp
```

It is a remote MCP server over HTTP (what some tools call "Streamable HTTP"), so there is nothing to install or run on your computer. Wherever a tool asks for a connector, a remote MCP server or a server URL, this is the address to give it.

## Approving the Connection

The first time your tool connects, it opens a liveworkspace page in your browser:

<Step n={1}>
  Sign in to liveworkspace, if you aren't already.
</Step>
<Step n={2}>
  Check the page. It is titled **Connect** followed by your tool's name, and it says which site the
  access goes to. Only continue if you recognise that site. For a tool on your own computer
  (such as Claude Code or Cursor) the access goes to an address such as `localhost:55884`:
  continue if you started the connection yourself.
</Step>
<Step n={3}>
  The page lists each liveworkspace app, ticked. Clear any app you don't want this tool to reach.
  Switch on **Read-only access** if the tool should only find and read your <Noun plural />, never
  change them.
</Step>
<Step n={4}>
  Choose **Connect**. The browser hands you back to your tool, and the connection is ready.
</Step>

Approving creates an [API token](/help/account-and-data/api-tokens/) named after the tool, which you can revoke in **Settings**, **Developers**, **API Tokens** (in any liveworkspace app, or on [liveworkspace.app](https://www.liveworkspace.app/explorer?settings=tokens)) to disconnect it. It lasts six months; reconnect the tool after that. Connecting the same tool again replaces its earlier token, so it doesn't use up another.

## Claude

Once <AppName /> is listed in Claude's connector directory, open **Settings**, then **Connectors**, browse the directory, find **liveworkspace** and choose **Connect**: no address to paste. Until then, add it as a custom connector:

In Claude on the web, open **Settings**, then **Connectors**, and add a custom connector. Name it "liveworkspace", paste the address above as its URL, and add it. Then choose to connect it, and approve the connection on the liveworkspace page that opens.

On a Team or Enterprise plan, an owner of your Claude organisation may need to add the connector before members can connect it. Exact menu names in Claude can change between versions; look for custom connectors in its settings.

## Claude Desktop

Claude Desktop uses the same connectors as Claude on the web: a connector you add there appears in the desktop app when you are signed in to the same Claude account, and you can add one from the app's own **Settings**, **Connectors** in the same way. Approve the connection when the liveworkspace page opens in your browser.

## Claude Code

Add the server from your terminal, with `liveworkspace` as NAME and the address above as ADDRESS:

```bash
claude mcp add --transport http NAME ADDRESS
```

Then, in a Claude Code session, run `/mcp`, choose `liveworkspace`, and authenticate: your browser opens the liveworkspace approval page. Add `--scope user` to the `claude mcp add` command to make it available in every project rather than only the current one.

<AppNote app="liveplanner">
  `--scope user` makes it available in every project on your computer.
</AppNote>

If you'd rather use an API token than sign in through the browser, pass it as a header instead:

```bash
claude mcp add --transport http NAME ADDRESS \
  --header "Authorization: Bearer lwt_..."
```

For coding agents working in a repository, the [<AppName /> CLI](/help/developers/cli/) is an alternative to the MCP server: both use the same API and the same kind of token.

## Cursor

Add liveworkspace to Cursor's MCP configuration: `~/.cursor/mcp.json` for every project, or `.cursor/mcp.json` inside one project.

```json
{
  "mcpServers": {
    "NAME": {
      "url": "ADDRESS"
    }
  }
}
```

Use `liveworkspace` as NAME and the address above as ADDRESS. Cursor then lists it in its MCP settings and offers to sign in to it, which opens the liveworkspace approval page. To use an API token instead, add a `headers` entry beside `url`:

```json
"headers": { "Authorization": "Bearer lwt_..." }
```

## ChatGPT

Where your ChatGPT plan lets you add custom connectors (it is part of ChatGPT's developer mode, and the wording varies by plan and version), create a new connector, paste the address above as its MCP server URL, and choose OAuth for authentication. Approve the connection when the liveworkspace page opens.

## Any Other MCP Client

Any tool that supports remote MCP servers can connect. Add a remote server (HTTP) with the address above. If the tool supports signing in to servers (OAuth), it finds the sign-in by itself: there is no client id or secret to enter. If it doesn't, use an API token, below.

## Using an API Token Instead

Some tools can't sign in to a server, or you may want to set one up from a script or a config file. Instead of approving the connection in the browser, you can give the tool an API token as a header on every request:

```text
Authorization: Bearer lwt_...
```

<Step n={1}>
  Create a token in **Settings**, **Developers**, **API Tokens**, in any liveworkspace app or on
  [liveworkspace.app](https://www.liveworkspace.app/explorer?settings=tokens) (see [API
  Tokens](/help/account-and-data/api-tokens/)), and copy its secret: it is shown once.
</Step>
<Step n={2}>
  In your tool, add the MCP server with the address above, and set the `Authorization` header to
  `Bearer` followed by a space and the secret.
</Step>

Tick **Read only** when you make the token if the tool only needs to look. Treat the secret like a password, keep it out of files you share or commit, and revoke the token when you stop using the tool.


## Ask Across Apps

One connection reaches every app you ticked, so a single request can start in one app and finish in another. Name the app, or the thing you want made, so the tool picks the right one:

- "Find my **liveplanner** plan about the launch, then write its status up as a **livedocuments** article and share a link."
- "Turn the cards in my **liveplanner** retro board into a **livediagram** mind map."
- "Read the Release Runbook in our **liveknowledge** knowledgebase and draw its steps as a **livediagram** flowchart."
- "Make a five-slide **livedocuments** deck from my **livediagram** diagram about onboarding."
- "Search our **liveknowledge** knowledgebase for how we handle refunds, then add a card for each gap to my **liveplanner** support board."

Each app also has its own starter prompts on its Build with AI page, and [liveworkspace.app's](https://www.liveworkspace.app/ai#prompts) has more that cross apps. Every one names its app for the same reason.

## Moving From an Old App Address

Before the one address, each app had its own (for example `mcp.livediagram.app`). Those addresses take no new connections: a connection you made to one keeps working only until its token ends, and signing in there again points you to the one address. To switch:

<Step n={1}>
  In your tool, remove the server you added for the app.
</Step>
<Step n={2}>
  Add the one address above once, named `liveworkspace`, and approve it, keeping every app you use ticked.
</Step>
<Step n={3}>
  Revoke the old connection's token in **Settings**, **Developers**, **API Tokens**, if it is still listed.
</Step>

Your work isn't affected: it lives in your account, not in the connection.

## If It Doesn't Connect

- **The page says "This link has expired" or "This request has expired"**: a connection request lasts ten minutes. Start the connection again from your tool.
- **It says your account has reached its limit of API tokens**: you can have 20 unexpired tokens. The page lists them under the message: choose **Revoke** on one you no longer use (the least recently used come first), then **Connect**.
- **The tool keeps asking you to sign in**: the token it held may have expired or been revoked. Remove the connection in the tool and add it again.
