# Share password

A document's share password is the index's: one password guards every link to the item (`PUT /items/:id/share-password`), set, changed or removed in the shared Share dialog.

liveknowledge asks for it. A link visitor whose link needs a password sees the password gate (`../packages/workbench/src/components/dialogs/SharePasswordGate.tsx`, in this product's word through `apps/editor/components/dialogs/SharePasswordGate.tsx`); the password is kept for the tab's session and sent with the share code (`X-Share-Code`, `X-Share-Password`) when the editor asks the index for a grant. The index answers 401 `password_required` or 403 `password_invalid`, and the gate says which.

**The restricted page.** A document can also ask everyone who opens a link to sign in, optionally with an account at one of its email domains (the index's sign-in rule, [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Sharing and access"). The index refuses a guest or nobody `401 sign_in_required` and an account at another domain `403 domain_not_allowed`, each with the rule's `domains`, before it reads the password. The share resolve (`apps/editor/lib/api/share.ts`, through `shareGateOf` in `@liveworkspace/workbench/lib/share-restriction`) turns either into the gate with `restricted`, on both of its paths: the index's resolve of a bare code, and the grant asked with the document's id (`/document/<id>?s=<code>`), whose refusal keeps its domains (`documentGrantRefusalDomains`). The gate's place then shows the restricted page (`ShareRestricted` in the workbench, titled "Sign In Required"): Sign In and Create Account for a guest, Use Another Account (`screen=switch`, `prompt=login`) for another domain's account, which names the domains the link is for and says the visitor is signed in as a different account (by its email when the page knows it). Each comes back to the same address, where the link opens with its role. A remembered password is kept: the rule refused the visitor, not it. Only a code the index does not know, or one turned off, shows Link Not Valid.

**Reopened by its own address.** A visitor who opened the document through a password-protected link and reopens it by its own address (`/document/<id>`, from Shared with me, Recent or a bookmark) sends no code. The index's grant refusal then names the link (`401 password_required` with `link`, [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Reopened without the code"), and `openOwnAddress` (`@liveworkspace/workbench/lib/editor-arrival`) opens the document through that link: the password this browser remembers under its code opens it straight away, and with none (or a changed one) the password gate shows, never Not Found. Each try at the gate goes straight through that link, not the refused own-address load again, and that refusal is not counted as an api error. The address stays the document's own; the visitor opens at the link's level and tab, carrying its code.

The document is [one-explorer.md](../../../../liveworkspace/docs/specs/004-index/one-explorer.md); the calls and types are in [one-explorer-contracts.md](../../../../liveworkspace/docs/specs/004-index/one-explorer-contracts.md) "Sharing and access". The Explorer that shows it is the shared package, [`@liveworkspace/explorer`](../../../../packages/explorer/README.md).
