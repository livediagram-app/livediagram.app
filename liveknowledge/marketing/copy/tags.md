# Tags & keywords

One-word tags for directory listings, app stores, GitHub topics and Product
Hunt. Ranked by how tightly they fit the product, then split by platform so you
can paste the right set into each field.

Built from [`facts.md`](facts.md). No tag may imply a feature liveknowledge
doesn't have (see "Out of scope" there): that means no `slides`,
`presentations`, `infographics`, `database`, `whiteboard` or `selfhosted`.

## Ranked by fit

**Tier 1, core identity (use these first, almost everywhere)**

`knowledgebase` · `knowledge-management` · `documentation` · `team` ·
`verification` · `ai` · `mcp`

**Tier 2, strong supporting**

`collaboration` · `realtime` · `opensource` · `free` · `agents` · `search`

**Tier 3, context-dependent (when a directory wants more, or is dev-focused)**

`markdown` · `cli` · `mit` · `notion-import` · `confluence-import` ·
`nextjs` · `cloudflare` · `typescript`

## Judgment calls

- **`wiki`** is how people search for this category, so it is allowed as a
  tag and a category on a directory that has one. It is never the product's
  own noun in prose: the product is a knowledgebase.
- **`knowledge-base`** (two words, hyphenated) is allowed as a tag where a
  directory's own vocabulary has it. In prose it is always one word.
- **`ai`** means two real things here: Ask (cited answers on the team's own
  Claude or OpenAI key) and the MCP server for agents. Don't use `ai-assistant` or
  `chatbot`: there is no built-in model.
